通过详细的调试日志分析，我们终于找到了第7条内容"丢失"的真正原因。

### ❌ 真正的问题：Chrome渲染窗口截断

**根本原因**：Chrome渲染器的窗口高度设置不当，导致内容被截断。

#### 🔍 问题详情

1. **内容实际高度**: 1840px
2. **Chrome窗口高度**: 1440px（固定值）
3. **结果**: 底部400px的内容被截断，第7条内容位于被截断的区域

#### 📋 证据链

```
🔍 调试：列表元素最终高度: 1704px
🔍 调试：可用高度=1320px
✅ 超长图HTML生成完成，总高度: 1840px
🖥️ 开始渲染超长图，高度: 1840px
Chrome渲染超时 (超时时间: 30s, 图片高度: 1840px)
```

**问题流程**：
1. 内容总高度1840px > Chrome窗口高度1440px
2. Chrome只能渲染窗口范围内的内容
3. 超出窗口的400px内容（包含第7条）被截断
4. 用户看到的图片只包含前6条内容

## 🛠️ 修复方案

### 1. 动态窗口尺寸调整 ✅

**修复前**：
```go
chromedp.Flag("window-size", fmt.Sprintf("1080,%d", totalHeight))
```

**修复后**：
```go
windowHeight := totalHeight + 200 // 添加200px缓冲区
chromedp.Flag("window-size", fmt.Sprintf("1080,%d", windowHeight))
```

**改进**：
- 根据实际内容高度动态设置窗口大小
- 添加200px缓冲区确保内容完整显示
- 匹配视口大小与窗口大小

### 2. 超时时间优化 ✅

**修复前**：
```go
renderTimeout := 30 * time.Second
if totalHeight > 2000 {
    renderTimeout = 60 * time.Second
}
```

**修复后**：
```go
renderTimeout := 45 * time.Second // 基础超时增加
if totalHeight > 1500 {
    renderTimeout = 60 * time.Second
}
if totalHeight > 2500 {
    renderTimeout = 90 * time.Second
}
```

**改进**：
- 更合理的超时时间梯度
- 针对不同高度的图片设置不同超时
- 避免大图片渲染超时

### 3. 视口与窗口同步 ✅

**修复前**：
```go
chromedp.EmulateViewport(1080, int64(totalHeight))
```

**修复后**：
```go
chromedp.EmulateViewport(1080, int64(windowHeight))
```

**改进**：
- 确保视口大小与窗口大小一致
- 避免尺寸不匹配导致的渲染问题

### 4. 增强错误信息 ✅

**修复前**：
```go
fmt.Errorf("Chrome渲染超时 (超时时间: %v, 图片高度: %dpx): %v", renderTimeout, totalHeight, err)
```

**修复后**：
```go
fmt.Errorf("Chrome渲染超时 (超时时间: %v, 内容高度: %dpx, 窗口高度: %dpx): %v", renderTimeout, totalHeight, windowHeight, err)
```

**改进**：
- 提供更详细的调试信息
- 便于问题排查和优化
