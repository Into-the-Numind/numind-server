# 最终切分策略（简化版）

## 🎯 核心原则

**极简策略，就两条规则：**

```
1. 文本 < 500字符：不切分，直接整体处理
2. 文本 >= 500字符：用语义切分（AI理解内容后切），AI不可用时用规则切分
```

---

## 📋 详细流程

### 情况一：短文本（< 500字符）

**处理**：**不切分**

**直接返回**：一个完整的 chunk

**原因**：
- 500字符以内，通常就是一个完整的段落或几句话
- 没必要切，切了反而破坏完整性
- 直接整体处理，简单高效

**例子**：
```
输入："今天天气很好，适合出游。我们的产品功能强大，价格实惠。"
（假设100字符）

输出：1个chunk，包含完整文本
```

---

### 情况二：长文本（>= 500字符）

**处理**：**优先语义切分**

**具体流程**：
1. 检查 AI 模型是否可用（bge-small-zh 是否下载好）
2. **可用** → 用 **EmbeddingSplitter**（语义切分）
   - AI 理解内容
   - 在主题转换处切分
   - 不切在句子中间
3. **不可用** → 降级用 **EnhancedMarkdownSplitter**（规则切分）
   - 按标点切分（优先句子边界）
   - 尽量不切在句子中间

**例子**：
```
输入：一篇2000字的产品说明书

输出：多个chunks，每个在主题转换处切开
Chunk 1: 产品介绍部分
Chunk 2: 功能特性部分
Chunk 3: 价格方案部分
...
```

---

## 🔍 专有名词对照

| 名词 | 大白话 | 作用 |
|------|--------|------|
| **HybridSplitter** | 混合切分器 | 总指挥，决定用哪种方式 |
| **500字符阈值** | 切分门槛 | <500不切，>=500才切 |
| **EmbeddingSplitter** | 语义切分器 | AI理解内容后切分，质量高 |
| **EnhancedMarkdownSplitter** | 增强规则切分器 | 按标点切分，保底用 |
| **Semantic Available** | AI是否可用 | 检查模型是否下载好 |
| **Chunk** | 切片/块 | 切分后的文本块 |

## 📊 对比旧策略

### 旧策略（复杂，有问题）

```
< 2000字符 → 规则切分（可能切碎）
>= 2000字符 → 语义切分
```

**问题**：
- 1999字符用规则切分（可能切在句子中间）
- 2001字符用语义切分
- **差2个字符，策略完全不同**

---

### 新策略（简单，合理）

```
< 500字符 → 不切（保持完整）
>= 500字符 → 语义切分（AI切，质量好）
```

**优点**：
- 短文本保持完整，不破坏
- 长文本用AI切，质量高
- 逻辑简单，没有歧义

## 🎬 实际例子

### 例子1：简短问候（200字符）

```
内容："您好！欢迎咨询。我们提供产品销售服务，欢迎选购。联系方式：xxx"

处理：< 500字符，不切分
输出：1个chunk（完整内容）
```

---

### 例子2：中等长度产品介绍（800字符）

```
内容："## 产品功能\n\n我们的智能助手可以帮助您...（800字符）"

处理：>= 500字符，用语义切分
输出：2-3个chunks
- Chunk 1: 功能介绍部分
- Chunk 2: 使用说明部分
```

---

### 例子3：长文档（3000字符，AI可用）

```
内容：完整的产品手册...

处理：>= 500字符，AI可用 → 语义切分
输出：多个chunks，在主题转换处切开
```

---

### 例子4：长文档（3000字符，AI不可用）

```
内容：完整的产品手册...

处理：>= 500字符，AI不可用 → 降级规则切分
输出：多个chunks，尽量在句子边界切开
```

---

## 🔧 如何查看实际策略

开启调试日志：

```bash
docker run -e SPLITTER_DEBUG=1 ...
```

查看日志：

```bash
# 短文本
docker logs numind-server-dev | grep "no splitting"
→ "[HybridSplitter] Text < 500 chars, no splitting needed"

# 长文本，语义切分
docker logs numind-server-dev | grep "semantic splitting"
→ "[HybridSplitter] Text >= 500 chars, using semantic splitting"

# 长文本，规则切分（降级）
docker logs numind-server-dev | grep "fallback"
→ "[HybridSplitter] Semantic unavailable, fallback to rule splitting"
```

## ✅ 总结

| 文本长度 | 处理方式 | 结果 |
|----------|----------|------|
| < 500字符 | **不切分** | 1个完整chunk |
| >= 500字符 + AI可用 | **语义切分** | 多个chunks，主题边界 |
| >= 500字符 + AI不可用 | **规则切分** | 多个chunks，句子边界 |

**核心思想**：
- 短文保持完整
- 长文用AI切
- 简单直接，没有歧义
