# 飞书历史授权卡片恢复设计

## 根因

2026-07-16 的开发环境日志显示，用户点击的卡片属于旧实现生成的状态：等待中的飞书任务摘要仍指向会话 `S`，但 `S` 已被标记为 `superseded`。旧实现曾创建另一个会话却没有把任务摘要重绑到它，因此现有恢复逻辑有意拒绝了这张卡片并映射为 500。

新实现不会产生该状态；本次仅为已经存在的历史记录提供受限兼容恢复。

## 决策

只有同时满足以下条件时，允许将 `superseded` 的会话当作一次刷新来源：

1. 会话属于当前用户和当前飞书代际；
2. 会话关联同一等待任务；
3. 任务摘要精确指向这个会话，而不是任意“最近会话”；
4. 任务状态、授权阶段和权限范围一致。

满足时，复用现有的事务性替换：创建新会话、更新摘要、保持旧会话作废，并在提交后启动/放行新工作器。这样不会重新启用旧链接，也不会扩大会话查找范围。

## 安全约束

- 仅接受 `pending`（正常路径）或上述精确 `superseded`（历史兼容路径）状态；失败、完成、跨任务或摘要不匹配的会话继续拒绝。
- 事务仍锁定账号、源会话和任务；不保存临时 URL、设备码或凭据。
- 手动连接不走该兼容路径。

## 测试

1. 生命周期测试复现历史状态：刷新返回新授权动作，而不是 500。
2. 存储/授权服务测试验证历史源会话仍需满足任务摘要、阶段和权限范围围栏。
3. 运行飞书包测试、全仓测试与 lint。
