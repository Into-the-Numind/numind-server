# 飞书创建个人应用完成态修复设计

## 根因

创建个人应用使用固定命令 `lark-cli config init --new`。该命令支持交互式/文本完成输出，不提供 `--json` 参数。受控执行器却将所有授权命令统一要求为 JSON 成功回执，因此命令已经成功退出时仍被拒绝，工作器在读取并校验临时应用配置之前把会话标记为 `failed`。

## 设计

### 1. 按命令定义完成证据

执行器保留命令白名单、参数校验、退出码、输出限制、官方 URL 校验和进程清理。

- `config init --new`：成功退出即可进入下一步；`runWorker` 必须再调用已有的 `AppIDFromHome`。该函数只从受控临时目录读取完整 app ID/secret 配置，作为创建完成证明；密钥不写日志、不返回 API。
- 其他授权命令（例如 `auth login --json`）：继续要求 JSON 成功回执，不改变其协议。

这不是把文本输出普遍当作成功，而是将每个固定命令的协议与它实际可提供的证据对齐。

### 2. 受限重试当前失败卡

刷新动作只可接纳 `pending` 或任务摘要精确绑定的 `failed` 源会话。失败源走现有的事务性替换：创建替代会话、重绑同一任务摘要、作废旧会话、提交后放行新工作器。

数据层同时把 `failed` 纳入来源状态，但保留既有用户、账号代际、任务 ID、授权阶段、权限范围的精确匹配。任何同任务同阶段的活动未过期替代会话，不论权限范围，都会阻止重试，避免并发创建。

## 非目标

- 不改飞书 CLI 版本、不新增权限、不改前端或 API。
- 不恢复任意历史失败会话；不把链接、设备码、应用密钥持久化。

## 测试策略

1. 伪 CLI 模拟真实 `config init --new` 的文本完成输出和完整配置，先证明旧执行器错误拒绝，修复后允许后续配置校验。
2. 生命周期、授权服务与存储测试覆盖“当前绑定失败卡可以重试”和并发替代会话拒绝。
3. 运行聚焦测试、`task lint` 与 `task test`。
