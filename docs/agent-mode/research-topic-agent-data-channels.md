# 选题 Agent 数据通路与业界方案调研

> 来源：deep-research workflow（2026-06-10，105 agent / 23 来源 / 98 条声明 → 22 条经 3-0 对抗核实确认 + 3 条被证伪）。综合步骤因网络中断未跑，本文由主 session 据已核实事实综合。
> 目的：为"选题 Agent"的数据能力设计在 Hybrid / 三方 API / 自建抓取 三档间做有依据的取舍。

---

## 一句话结论

**市面上不存在合规的"开箱即用小红书数据 API"通路。** 官方开放平台只有电商 API（无任何内容/榜单/爆款数据）；三方数据商（千瓜/灰豚/新红）全部不开放 API，只卖人用 SaaS；开源方案（MediaCrawler/xhs-mcp）要么明确禁止商用、要么靠签名逆向/浏览器自动化绑真账号（封号+合规风险），不能嵌进给客户交付的商业产品。**三档实际收敛为一个答案：v1 走 Hybrid（人喂素材+agent 拆解改编），因为另外两档要么买不到、要么不能碰。**

---

## 子问题①：成熟产品怎么做（已核实事实）

产品分两类，没有第三类把"实时小红书数据"当 API 卖：

| 产品 | 形态 | 数据来源 | 商业模式 | 来源 |
|------|------|---------|---------|------|
| **新红 (newrank)** | 实时热点追踪（站内/站外热搜词、热门话题）+ 爆文深度分析 + 24h 关键词监测任务 + 分钟级直播监测自动报告 | **官网不披露**（仅"收录海量账号及创意素材"） | SaaS 订阅 + 销售接洽，**无公开 API/价格** | xh.newrank.cn |
| **千瓜数据** | 榜单 + 达人/笔记检索 + 行业报告（人用看板） | 三方采集 | SaaS：高级版 ¥1599/月、专业版 ¥2599/月（5 子账号）；**无 API 产品条目**，定制需联系客服 | qian-gua.com/Home/AllPrice |
| **灰豚数据** | 多平台数据看板 | 三方采集 | **明确"不提供任何 API 接口服务，如需使用数据请直接开通会员"**（注：帮助页 2021-2022，现状需复核） | huitun.com/help |
| **站长AI 某书选题灵感** | 纯 prompt 生成：输入主题→AI 输出选题 | **无数据来源**（纯 LLM 生成，"爆款"二字无数据支撑链路） | 免费工具 | ai.chinaz.com/red-book/inspiration |
| 海外对照（MrBeast 前内容策略师创业） | AI 创作者选题 + 分析工具 | — | 在建 | techcrunch 2025-11-24 |

**关键洞察**：头部工具（新红/千瓜）是"**数据库查询**"形态——它们自建数据（怎么搞的不公开，大概率多年自建抓取+积累），把榜单/监控/检索给人看；而"纯 AI 选题"工具（站长AI）**根本没数据，纯编**。我们预探针 run #114 的产出质量（二手可信源+真实归纳，零编造）已经**强于站长AI 这类纯生成工具**。

> 被证伪修正（1-2）：不能断言新红"只有数据库查询、无生成式 AI 选题"——核实发现其也有 AI 能力，非纯数据库。

## 子问题②：数据通路盘点（已核实事实）

| 通路 | 现状 | 合规/风险 | 能用吗 |
|------|------|----------|--------|
| **小红书官方开放平台** | = **电商**开放平台。API 全是电商域（商品/订单/跨境/售后/财务/会员通/电子面单），**文档树中不存在任何笔记内容、榜单、爆款数据 API**。资质门槛高（企业资质审核，个人/个体店铺被排除） | 合规但**无内容数据** | ❌ 此路不存在 |
| **三方数据商 API（千瓜/灰豚/新红）** | 三家**都不开放 API**，只有人用 SaaS 看板 | — | ❌ 买不到 API |
| **开源 MediaCrawler** | 支持小红书+6 平台，关键词搜索/笔记 ID/评论/创作者主页；Playwright 浏览器自动化保登录态（**绑真账号→封号风险**） | **明确禁止商用、用户自担一切法律责任** | ❌ 商用合规阻断 |
| **开源 xhs-mcp** | MCP server，暴露 search_notes / get_note_content / get_note_comments / home_feed / post_comment；JS 逆向 x-s/x-t 直连 HTTP（比浏览器自动化轻） | 逆向签名本身有封号/接口变更风险（注：该项目无 MediaCrawler 那种明确商用免责声明——0-3 证伪了"它带禁商用免责"的说法，但**逆向路线的风险不因此消失**） | ⚠️ 技术可行，合规存疑，嵌商业产品风险落到有数+莫小派 |
| 聚合 API 中间商（如 explinks 等） | 调研命中但来源质量标记 **unreliable** | 未核实 | ⚠️ 需亲验，存疑 |

## 子问题③：Agent 能力模式（已核实事实）

Anthropic《Building Effective Agents》（业界最权威参考）：

- **workflow vs agent 二分**：workflow = LLM+工具按预定义代码路径编排；agent = LLM 动态自主指挥流程与工具。
- **从最简起步**："对很多应用，优化'单次 LLM 调用 + 检索 + 上下文示例'通常已经足够，无需构建完整 agent 系统。"
- **何时用 full agent**：步骤数难以预测、无法硬编码固定路径的开放式问题；反之（固定流程的选题日报/榜单摘要）应用 workflow。
- **最成功的实现用简单可组合模式**，非复杂框架（5 种 pattern：prompt chaining / routing / parallelization / orchestrator-workers / evaluator-optimizer）。

LangChain 生态实证：

- **social-media-agent**：发布前**强制 human-in-the-loop**（Agent Inbox 人审改/接受/拒绝才发）——内容 agent 把人审做成架构内置环节而非可选项。
- **Agent Builder 模板库**含现成 "Social Media Monitor"（监控 X + Slack 每日摘要）——"**平台/账号监控 + 定期摘要推送**"是头部 agent 平台产品化的标准内容监控 pattern。

**对应到我们的四档候选**：
1. 纯搜索增强 → 我们现状（web_search+web_fetch），预探针 B+，方向级选题够用、缺站内实时数据
2. 外接垂直数据源工具 → 需要②里"能用"的数据通路，目前**无合规通路可接**
3. 人喂素材+AI 拆解 hybrid → Anthropic"单次 LLM+检索够用"+social-media-agent"人喂+HITL"双重背书
4. 账号监控+定期摘要 → LangChain 已产品化的标准 workflow pattern（**未来主动选题/日报的形态**）

## 对我们的建议（三档）

### ✅ Hybrid（零开发）—— v1 采用

- **形态**：人（莫小派流量小组/学员）把刷到的爆款笔记（URL/截图/正文）喂给 agent，agent 做**拆解结构 + 提炼选题逻辑 + 移植改编**到学员赛道。二手可信源（媒体报道/行业报告/官方话题数据）做方向补充。
- **为什么**：① 业界双重背书（Anthropic 最简起步 + LangChain social-media-agent 实际就是人喂+HITL）；② 零封号、零合规风险；③ 零新开发；④ 预探针已证 agent 的"拆解+改编"能力达标；⑤ **恰好贴合北极星**"专家出方法论、agent 出力"——人提供"什么是好爆款"的判断，agent 提供规模化的拆解改编力。
- **R1 验证点**：莫小派专家的真实选题方法论，是否"喂素材+拆解改编"就能覆盖，还是强依赖"系统自动发现实时爆款"。

### ⚠️ 三方数据 API（中）—— 实际买不到，降级为"待验证"

- 调研硬结论：千瓜/灰豚/新红**都不开放 API**。这档不是"要不要做"，是"**有没有得做**"——目前没有。
- 唯一残余可能：聚合 API 中间商（explinks 类，来源 unreliable 需亲验）。若 R1 后确认莫小派强需实时数据，再花半天亲验这类中间商的真实可用性+定价+合规，作为独立 spike。
- 不作为 v1 阻塞项。

### ❌ 自建抓取（重）—— 不做

- MediaCrawler 明确禁止商用；xhs-mcp 等靠逆向签名/浏览器自动化绑真账号。封号 + 合规 + 维护三重风险，**嵌进给客户交付的商业产品 = 法律风险直接落到有数和莫小派头上**。
- 明确排除出 v1 和可预见的 v1.x。除非有专门的法务+风控资源，否则不碰。

---

## 对 design-baseline 的回写

- CAP-1 最终建议：**v1 = Hybrid（纯搜索增强 + 人喂素材拆解）**，不接外部数据源。能力天花板取舍（实时站内数据）留给 R1 用真方法论检验真实需求。
- 能力面新增（未来路线，非 v1）：**"账号监控 + 定期选题摘要" workflow**（LangChain 已验证的标准 pattern）——这是 agent mode 从"被动问答"走向"主动交付"的方向，但属 v2+。
