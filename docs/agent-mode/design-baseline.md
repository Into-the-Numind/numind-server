## §1 北极星

> **有数的 Agent mode = 机构把"繁琐且有价值的工作"封装成数字员工：专家出方法论，agent 出力，学员零门槛收获结果。**

- **产品命名**：产品叫**有数**（youshu.asia）；"莫小派"是首个机构客户的名字（代码库沿用）。
- **战略位置**：与 SOP、Chatbot 并列的第三模态（前两个模态已被莫小派大量使用并交付其客户）。Agent mode 是"能力更强的模式"——不靠堆功能防止系统臃肿，靠可配置的通用能力替代繁琐工作。
- **核心范式**：类 Claude-Code 全自主多轮工具调用（用户出任务，agent 自主完成，过程透明可取消）。✅ 与现状一致。
- **成功判据（用户 2026-06-10 原意）**：agent **真能完成复杂任务**——① 网页自主浏览/资料收集/信息爬取 ② 工具调用 ③ 图片（v1）/视频（v1.5）创作与剪辑——真正替代繁琐且有价值的工作。界面好看、功能齐全都不是判据。
- **锚定场景**：莫小派"**找选题 Agent**"——学员/流量小组发小红书视频笔记不知道发什么 → agent 全网寻找爆款选题 → 给出改编移植建议。现状痛点：人工刷小红书提取灵感，耗时极大，学员面对海量内容人脑过载且大部分人是懒惰的。

## §2 角色与关系模型（R0-T2 确认）

- **只有父账户（机构）可配置**；**使用全员开放**（父账户日常用 + 子账户用），gate = 会员在期 + 积分允许。
- **配置者画像**：机构内的**领域专家**（谁擅长哪个领域谁配置），**对技术一窍不通**。配置的本质难点 = 把专家脑子里的方法论挖掘出来，使 agent 执行效果最好。
- **子账户 = 纯使用者，零配置**。学员是"懒"的：agent 必须把活干到学员几乎不用动脑。
- admin 端仅监控。✅ 与现状一致。

## §3 入口与会话（R0-T3）

- **D-1（设计出入，待改）**：agent 入口应在"**工作区**"——与 SOP/chatbot 并列再加一个 agent 卡片区域，每个 agent 一个卡片模块。不是现在的独立 `/agent/chat` 菜单入口。
- 多人格卡片模式 ✅；按 agent 分会话（每 agent 多会话+历史侧栏）✅。

## §4 配置模式（R0 核心产出）

配置分两层，**v1 只做第一层**：

### v1 = 陪跑式配置（concierge）

- **方法论挖掘靠"有数创始人访谈专家"完成**（人对人），不靠产品功能。平台方完全不懂领域也能工作——配置过程的挖掘能力 v1 由人承担。
- 创始人把访谈结果写成 agent 的**方法论文档**（载体 = skill 正文 / agent 行为指引）。
- **专家触点 ≤5 分钟**：试聊草稿 agent → 口头提修改 → 创始人改 → 再试。
- v1 配置端只需服务两个人：**创始人**（高效建壳 + 直接编辑方法论正文）+ **专家**（一键试聊、零学习成本）。

由此对现状的裁决：

| 项 | 裁决 |
|----|------|
| "试聊"按钮（现为空 toast） | **P1 必修**：跳转聊天页跑草稿 agent（用户拍板"跳转聊天页即可"） |
| 方法论正文（custom_skill_body）编辑 | **升 v1 必修**（现状不支持 PATCH 编辑——创始人的核心操作路径） |
| 8 题问卷 | 保留，**降级为"建壳"**（起名/人设/语气）；不承担方法论挖掘；具体题目在 R1 实战中边用边裁 |
| from-scratch 创建路径 | 保留；q6/q7 422 修复立即合并（2026-06-10） |
| 高级模式（空占位+不可逆切换） | **v1 藏掉入口**（创始人不需要，专家更不需要） |

### v2 = AI 访谈式配置（路线图，不阻塞上线）

把创始人的访谈产品化：配置助手对专家做根源性提问 → 自动生成方法论草稿 → 试聊中持续修正 → 专家完全自助。这是"5 分钟配置"的终极形态。等试点跑通后立项。

## §5 Skill 形态（R0-T5，用户原话要点）

- **skill 是一种形态，必须保留**：agent 能够调用 skill 的能力和形态、以及 skill 的创建和配置功能，都是核心，不裁。
- skill 在本设计中的角色 = **方法论的载体**（专家方法论 → skill 正文 → agent 执行时加载）。
- **Marketplace 终局定位 = 官方精品 skill 商店**：有数官方挑选精品 skill 上架，供各机构调用（未来出现第 2、3 个"莫小派"时复用）。**不是**现在实现的"机构互相脱敏发布/订阅"。
  - v1：裁出（当前只有一个机构客户，无调用对象）→ 隐藏入口，相关 bug 不修。
  - 后续重启时按"官方策展商店"重新设计（发布主体=平台官方，无需跨租户脱敏链路）。
- skill 版本历史/回滚：后端保留，前端 UI 不进 v1 验收面。

## §6 能力面 v1 in/out（R0-T6）

| 能力 | v1 | 说明 |
|------|----|----|
| 网页自主浏览/资料收集/爬取 | **in，但有最大风险** | 现状仅 web_search(Tavily)+web_fetch；**小红书是登录墙+反爬封闭生态，现有工具可能挖不到真实爆款** → R1 实战 = 能力探针，结果决定是否立项补能力（CAP-1） |
| 工具调用（ReAct 全自主+全开工具） | in ✅ | 现状满足 |
| 图片生成 | in ✅ | 现状满足 |
| 文档产出（xlsx/docx/pptx/pdf 平台 skill） | in ✅ | 保留 |
| **视频创作/剪辑** | **out → v1.5** | 现状为零，从零建设周期长；用户拍板试点先用浏览+工具+图片证明价值 |
| Marketplace | out → v1.x | 见 §5 |
| 高级模式 prompt 直编 | out | 藏入口；v2 访谈式配置时统一考虑 |
| L1/L2 记忆、多模态附件、ask_user_question | in（现状保留） | R2 学员端走查再细评 |

## §7 计费（R0-T7）

- 使用者扣**自己**的积分池（子账户扣子账户、父账户扣父账户）✅ 已实现并 dev 验证。
- 使用资格 gate = 会员在期 + 积分允许（**待硬基建复核**：代码是否按此 gate，见 backlog HW-30）。
- 试点期照常扣积分（莫小派 B2B grant 会员照旧）；agent 积分消耗速率高于 SOP/Chatbot，试点期观察，必要时调 per-session cap 默认值。
- 专家/创始人试聊计费：admin_test 池设计已有（ReserveAgentTest caller 缺失 HW-6 待复核）。

## §8 v1 范围决策记录（R0 拍板汇总，2026-06-10）

1. 定位=机构数字员工；并列三模态；全自主范式 —— 维持现状方向
2. 父配置/全员使用/子账户零配置 —— 维持现状
3. 入口改工作区卡片区（D-1）
4. 配置模式 v1=陪跑式（试聊 P1 必修 + 方法论编辑 v1 必修 + 问卷降级建壳 + 高级模式藏 + from-scratch 修复合并）
5. skill 形态保留；marketplace v1 裁、终局=官方店
6. 视频 → v1.5；浏览能力探针 = R1 第一仗（CAP-1）
7. R1 从"UI 走查"改为"实战建出选题 Agent"（能力探针+配置端走查+首个交付物三合一）

## §9 开放问题

- **CAP-1**：现有 web_search/web_fetch 对小红书选题场景的真实产出质量（R1 实战出结论；不通则立项补能力，状态=上线阻断候选）
- 学员端（R2）：运行时体验细则待走查（懒人原则的具体落点：默认任务入口？输出形态？）
- 问卷"建壳"的最终题目集（R1 实战中裁）
- 工作区卡片入口（D-1）的具体改造方案（R1 后出）
- 试点成功量化指标：用户当前以"能力达成"为判据，量化指标（学员周活/专家认可）上线后补充观察
