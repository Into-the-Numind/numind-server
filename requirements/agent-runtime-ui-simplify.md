# Agent 运行界面精简与真实停止

## 来源

- 提出人：用户
- 提出日期：2026-07-19

## 需求描述

用户要求精简 Agent 运行界面，并确保输入框内的停止按钮能够真实停止任务：

1. 输入框有内容后，界面不得显示“预计消耗积分”或同类预估消耗提示。
2. 删除首屏欢迎区中“🤖 + Agent 名称”的身份组件。
3. 删除运行时右上角“取消任务”按钮；输入框内的停止按钮成为唯一停止入口。
4. 验证并修复输入框停止按钮：点击后必须既终止浏览器端 SSE，也调用已有后端取消接口，使 Agent run 进入 `cancelled`，而非只关闭浏览器连接。
5. 将消息区“新内容”浮动控件改为仅保留向下箭头的圆形按钮，去除“新内容”文字。

## 业务目标

- 减少 Agent 界面中的重复信息和重复操作，让用户专注输入与产出。
- 保留一个明确、可验证的任务停止入口，避免用户误以为停止了运行而后台任务仍在继续。
- 降低浮动“新内容”控件的视觉占用，同时不牺牲回到底部的可发现性和键盘可访问性。

## 优先级

高（运行任务的停止语义必须正确，UI 简化与该行为一起交付）。

## Triage

- 推荐轨道：**Standard**
- 分类理由：
  1. 数据库 schema 变更：否。
  2. 新增 API 端点：否，复用已有 `POST /v1/agent-runs/:id/cancel`。
  3. 新外部服务集成：否。
  4. 影响文件数：**>3**（输入区、欢迎区、顶部栏、运行页、消息列表及 Playwright/单元回归覆盖）。
  5. 高风险业务逻辑（支付/权限）：否；但涉及 Agent 运行生命周期和用户可见的停止承诺，必须以端到端验证保护。
- 人类决定：用户已确认 Standard，并授权从 S0 执行至 Dev 部署。

## 备注

- 现状诊断：输入框停止键只调用 `AbortController.abort()` 关闭 SSE；右上角取消按钮才会调用 `cancelRun`。本需求删除右上角按钮前，必须把这两项语义合并到输入框停止键。
- 本期不改变积分计费的 Reserve/Reconcile 规则；仅隐藏输入前预估展示。实际取消后的既有后端对账语义保持不变。
