# Agent 卡片后实时流恢复

## 来源
- 提出人：用户（线上打标 Agent 使用者）
- 提出日期：2026-07-21

## 需求描述
打标 Agent 在出现外部操作卡片前，思考、正式文字和工具执行都能通过 SSE 实时显示；卡片完成后，用户只能看到执行动作，看不到后续思考和生成文字的实时更新，必须刷新页面才能看到已持久化的内容。

这次修复必须建立真正的卡片后实时事件通道，不得以定时轮询、刷新补数据或终态快照代替 SSE。

## 业务目标
- 用户在同一 Agent 任务中，不论是否出现飞书授权、外部操作或交互卡片，都能连续看到思考、正式文字和工具进度。
- 断线或页面短暂不可见后，可按事件序号恢复，不重复、不丢失、不串会话。
- 保留持久化快照作为最终一致性保障，但快照不再承担正常实时显示。

## 验收标准
1. 原始 Agent run 在卡片前的 `reasoning_delta` / `token_delta` / 工具事件仍逐帧显示。
2. 外部操作卡片完成并触发 detached continuation 后，后续思考、文字、工具开始/进度/结果和终态在无刷新情况下实时显示。
3. 浏览器重连携带已确认的最后事件序号，服务端仅补发后续事件。
4. 事件订阅必须校验当前用户对 run/session 的所有权，不得跨租户或跨会话泄露。
5. 连接中断时允许使用 run/snapshot 轮询作为降级，正常路径不依赖 5 秒轮询。
6. Playwright 以真实时间间隔发送“卡片前文字 → 卡片 → 卡片后思考/文字/工具”，并在流未结束前逐段断言 DOM 已更新。
7. 现有取消、多标签页防重、授权恢复、问题卡片和终态快照行为无回归。

## 优先级
高

## Triage
- 推荐轨道：Standard
- 分类理由：
  1. 数据库 schema 变更：否
  2. 新增 API 端点：是（已有 run 的可恢复事件订阅）
  3. 新外部服务集成：否
  4. 影响文件数：>3，跨后端与用户端
  5. 高风险业务逻辑：是（run 所有权、外部授权恢复、并发重连）
- 人类决定：用户确认按 Standard 从头执行到 dev 部署。

## 已确认根因
- 外部卡片后的 continuation 在服务端脱离原 HTTP/SSE 请求运行。
- `external_tool_resume.go` 会主动 drain 并丢弃 continuation 的 `stream.Event`，只保留持久化副作用。
- 前端只能在 5 秒状态轮询或刷新会话时读取快照，因此不是真正流式。

## 备注
参考 OpenAI Codex agent runtime 的 run/item 独立生命周期：工具 item 不会终止 turn 事件流，文字、reasoning 和工具均使用稳定 item ID 发送 started/delta/completed。
