# 飞书授权链接刷新后恢复任务失败修复

## 来源

- 提出人：用户
- 日期：2026-07-15
- 触发场景：用户在开发环境为“创建个人应用”刷新临时飞书授权链接后，完成飞书页面操作并点击“我已完成，继续”，页面显示 `Internal server error.`。

## 问题与目标

飞书个人工作区的授权会话有短时有效期。刷新链接会生成一个新的授权会话，但当前任务仍保存旧会话标识；同时，新会话在持久化绑定完成前没有被放行执行。结果是任务恢复时读取已失效的旧会话，返回 500，新链接也会在等待超时后失效。

目标是在刷新授权链接后，让原任务安全地、持续地绑定到新会话，并允许用户按正常流程继续，而无需重新发起原始任务。

## 验收标准

1. 对等待中的 `create_app` 授权链接执行刷新后，任务持久化记录中的会话标识和过期时间更新为新会话。
2. 只有在新的会话绑定已经持久化后，才放行该会话继续执行。
3. 用户随后点击“我已完成，继续”时，恢复流程读取新会话；会话仍待完成时返回正常的等待状态，而不是 500。
4. 旧会话不能为该任务完成授权；新会话仍必须属于同一用户、同一工作区代际、同一任务和同一授权阶段。
5. 不记录或输出授权链接中的一次性码、设备码或任何凭据。

## Triage

- 推荐轨道：Standard
- 判断：不涉及数据库 schema、公开 API 或新增外部服务；但修改的是第三方授权会话与任务恢复的持久化安全边界，且预计涉及业务层、存储层和回归测试，属于高风险授权逻辑。
- 用户确认：用户于 2026-07-15 明确要求“修复”。
