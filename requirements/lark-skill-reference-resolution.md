# 飞书技能参考文件简称安全解析

## 来源
- 提出人：产品负责人
- 提出日期：2026-07-19

## 需求描述
用户要求保留飞书技能参考文件的安全边界，但删除“AI 必须填写完整 `references/...` 地址”的要求。Agent 应能使用官方说明中的文件名简称，平台在服务端完成安全、唯一、可验证的规范化，避免 Agent 因内部路径格式反复失败。

## 业务目标
减少飞书 Agent 的无效内部试错，让正常任务不再因为补充说明路径格式而出现多次“执行出错”，同时继续阻止任意服务器文件读取、目录穿越和未声明资源访问。

## 优先级
高

## Triage
- 推荐轨道：Standard
- 分类理由：
  1. 数据库 schema 变更：否
  2. 新增 API 端点：否
  3. 新外部服务集成：否
  4. 影响文件数：预计 ≤3 个生产/测试文件，另含 NDF 工件
  5. 高风险业务逻辑（支付/权限）：是，修改受控内部资源读取边界
- 人类决定：确认使用快速 Standard，并授权自动执行到 Dev 部署

## 备注
- 不升级 lark-cli；版本升级另行处理。
- 不开放新的飞书技能、命令或用户数据能力。
- 已确认方向：不删除安全边界，只让完整内部地址对 Agent 隐形。
