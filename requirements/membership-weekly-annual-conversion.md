# 周会员转年会员订阅修复

## 来源

- 提出人：客户运营
- 提出日期：2026-08-10

## 需求描述

生产中，用户先持有周会员后被开通年会员时，月会员开通路径会沿用旧订阅行的 `weekly` 与 500 积分配置。已过期的周会员也会在重新开通年会员后遗留同样的配置。结果是年会员显示为每周期 500 积分，并可能把两次年会员开通累加为 24 个月。

## 业务目标

年会员必须始终采用月会员的订阅配置和每周期 2,000 积分。系统不得把有效周会员和年会员混合续期；运营需要在周会员有效期结束后再开通年会员，或通过单独的后续升级流程处理。

## 优先级

高（生产会员与积分账务正确性）。

## Triage

- 推荐轨道：Standard
- 分类理由：
  1. 数据库 schema 变更：否
  2. 新增 API 端点：否
  3. 新外部服务集成：否
  4. 影响文件数：≤3
  5. 高风险业务逻辑（会员/积分）：是
- 人类决定：2026-08-10 确认立即修复。

## 备注

生产数据已在同日通过受保护事务完成一次性校正；本变更只修复未来开通路径并加入永久回归测试。
