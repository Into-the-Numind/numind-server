# 飞书技能读取容错与平台分页

## 来源
- 提出人：产品负责人
- 提出日期：2026-07-19

## 需求描述
保留现有由 LLM 阅读官方飞书技能、判断业务动作并调用受控工具的架构。平台不替代 LLM 做业务判断，但要处理确定性的工具机械细节：不再让模型填写技能分页 cursor；当模型把明确的官方参考文件名误放进旧 `cursor` 字段时自动纠正；可恢复的参数错误不能在最终成功的任务中显示红色“执行出错”。

客户要求立即按快速 Standard 实现，自动完成合并、推送并部署 Dev。

## 业务目标
让任意用户创建的 Agent 都能稳定读取同一套官方飞书说明，减少与业务判断无关的字段抄写错误，同时继续严格限制可读技能、当前技能声明的参考文件和单次输出大小。

## 优先级
高

## Triage
- 推荐轨道：Standard
- 分类理由：
  1. 数据库 schema 变更：否
  2. 新增 API 端点：否
  3. 新外部服务集成：否
  4. 影响文件数：预计 ≤3 个生产文件，另含测试与 NDF 工件
  5. 高风险业务逻辑（支付/权限）：是，涉及 Agent 可读内部说明的白名单安全边界
- 人类决定：确认快速 Standard，并授权自动执行到 Dev 部署

## 备注
- LLM 继续决定读取哪个 skill/reference，以及后续执行哪条 Docs/Base/Wiki/Drive 业务命令。
- 不开放新技能、任意文件路径、shell、IM、身份参数或飞书业务命令。
- lark-cli 版本升级不属于本次改动。
