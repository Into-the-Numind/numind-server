# 飞书授权确认稳定性

## 来源
- 提出人：产品负责人
- 提出日期：2026-07-19

## 需求描述
用户完成飞书页面授权并点击“我已完成，继续”后，系统应在同一次请求内核对本次授权并立即恢复原 Agent 任务。授权任务和飞书链接均保持 10 分钟有效；官方 lark-cli 继续每 5 秒查询一次；前端最多等待 60 秒。系统必须严格核对本次链接、设备码、飞书应用、当前用户和原 Agent 任务，并输出不含凭据的结构化诊断日志。

## 业务目标
消除前端 30 秒超时造成的假失败，并使真实的飞书查询、协议或绑定错误能够被准确定位，同时不降低多用户、多 Agent 场景下的安全隔离。

## 优先级
高

## Triage
- 推荐轨道：Standard
- 分类理由：
  1. 数据库 schema 变更：否
  2. 新增 API 端点：否
  3. 新外部服务集成：否
  4. 影响文件数：>3
  5. 高风险业务逻辑（支付/权限）：是（第三方授权与 Agent 恢复）
- 人类决定：确认快速 Standard，自动推进至 Dev 部署

## 备注
- 保留用户手动点击继续，不增加自动确认。
- 不修改官方 CLI 的 5 秒轮询间隔。
- 不全局放宽所有 HTTP 请求超时。
