# 飞书个人工作空间连接完善

## 来源
- 提出人：Michael（产品/创始人）
- 提出日期：2026-07-13

## 需求描述
重新校准并完成有数的飞书连接能力。每个有数账号都可以连接该用户自己的飞书账号，并持续保持连接状态。连接完成后，Agent 可以在首次授权的权限范围内自动执行飞书操作，不需要每次写操作再次确认。

目标体验明确复刻 Claude Code 驱动飞书官方 CLI 的方式：用户向有数 Agent 表达“连接飞书”后，Agent 调用 lark-cli 推进个人自建应用的创建与授权；用户不手工填写 app_id/app_secret，只需打开 Agent 提供的飞书官方页面，完成创建确认和后续权限批准。所有必要步骤完成后，有数持续保有该用户的连接状态，后续 Agent 可直接访问其飞书工作空间。

首批业务能力聚焦：
- 把 Agent 结果写成飞书文档，并支持后续读取/更新文档所需的基础能力；
- 读取飞书多维表格，后续按真实业务闭环扩展必要的写入能力；
- 读取和使用飞书知识库内容；
- 授权失效、撤销或凭据异常时，明确提示用户重新连接，不静默失败。

现有 `feishu-integration` 实现只能作为待审计的技术资产，不能作为本需求的产品前提。新设计必须重新确认首次连接体验、长期凭据管理、解绑语义、账号隔离和真实端到端验收。

## 业务目标
让飞书成为每个用户 Agent 的长期个人工作空间：Agent 不只生成答案，还能在用户明确授权后持续读取其飞书资料，并把工作成果可靠地落回用户自己的飞书空间。

成功不以“接口已实现”衡量，而以真实用户能完成连接、跨重启保持连接、自动执行首批能力、失效后可恢复、解绑后权限确实终止为准。

## 优先级
高

## 备注
- 已确认连接模型的业务语义：每个有数账号连接自己的飞书账号，持续保持连接。
- 已确认首次连接采用“个人自建应用 + Agent 驱动 lark-cli”模型；用户只完成飞书官方页面上的创建确认与权限批准，不手工搬运开发者凭据。
- 已确认首次授权后，Agent 在授权范围内自动执行，不逐次确认。
- 已确认首批方向：飞书文档、多维表格、知识库。
- 已确认连接编排：不新增独立飞书 Agent。现有有数 Agent 通过专用连接工具调用确定性状态机，由状态机负责建应用、渐进授权、持久化、恢复和解绑；Agent 负责意图理解与恢复原任务。
- 已确认权限策略：首次连接不索取全部权限；首次使用文档、多维表格、知识库能力时按需增量授权，授权完成后自动恢复原任务。
- 已确认首版准入边界：仅支持有权创建个人自建应用、并能完成所需租户管理员审批的用户。普通员工无相应权限时，产品明确提示联系管理员；首版不自动降级到“有数共享应用”路径。
- 现状证据：dev 功能已部署但用户 HOME 数量为 0，无真实飞书 E2E；prod 未启用。
