# 飞书创建个人应用完成态修复

## 来源

- 提出人：有数用户
- 提出日期：2026-07-16

## 需求描述

用户完成飞书官方页面中的“创建个人应用”后，返回有数点击“我已完成，继续”得到 `Internal server error.`；重新生成的链接也会进入同一错误。

## 业务目标

让创建个人应用的真实完成信号被正确识别，且当前任务绑定的失败授权卡可以安全地重新生成链接并继续原 Agent 任务。

## 优先级

高

## Triage

- 推荐轨道：Standard
- 分类理由：
  1. 数据库 schema 变更：否
  2. 新增 API 端点：否
  3. 新外部服务集成：否，但涉及既有飞书授权生命周期
  4. 影响文件数：>3（授权服务、生命周期服务、存储和回归测试）
  5. 高风险业务逻辑（支付/权限）：是，授权状态与账户隔离
- 人类决定：延续已确认的飞书 Standard 开发，直接修复并部署开发环境验证。

## 备注

根因已由开发环境日志和受控 CLI 合约确认：`lark-cli config init --new` 没有 JSON 输出模式；现有通用执行器却强制要求 JSON 完成回执，导致正常完成被标为失败。应用配置中的完整 app 记录才是创建成功的后续证明。
