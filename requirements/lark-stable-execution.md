# 飞书 Agent 稳定执行

## 来源
- 提出人：产品负责人
- 提出日期：2026-07-19

## 需求描述
所有用户创建的任意 Agent 都应能在当前登录用户自己的飞书工作区内执行 Docs、Base、Wiki、Drive 受控业务命令。Agent 不再复制或维护平台内部技能票据；读取技能只用于理解命令。平台必须负责身份绑定、命令校验、权限检查、授权恢复、幂等和安全停止，并在前端把可自动恢复的试错显示为“处理中”，只把真正终止任务的失败显示为红色错误。

客户已确认采用“Agent 决策、平台执行与防护”的 B 方案，并授权快速 Standard 全自动执行直到部署 Dev。

## 业务目标
消除因 LLM 抄错内部票据、轻微命令形态差异或可恢复运行时错误导致的随机失败，让每个 Agent 的飞书能力像 Codex 一样稳定，同时不削弱账号隔离、权限和写入安全。

## 优先级
高

## Triage
- 推荐轨道：Standard
- 分类理由：
  1. 数据库 schema 变更：否
  2. 新增 API 端点：否
  3. 新外部服务集成：否
  4. 影响文件数：>3
  5. 高风险业务逻辑（支付/权限）：是，涉及飞书授权与写操作边界
- 人类决定：确认快速 Standard，并要求自动完成到 Dev

## 备注
- 保留当前用户与其飞书账号的一对一绑定。
- 继续禁止 IM、shell、auth/config/whoami 等非业务命令。
- 不使用进程内 receipt 缓存替代模型票据，因为多实例和重启会再次制造不稳定状态。
