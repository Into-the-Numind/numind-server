# 三 Agent 飞书内容生产流水线

## 来源
- 提出人：产品负责人
- 提出日期：2026-07-20

## 需求描述
把已经确认的三段业务 Prompt 定义成有数 AI 中三个可独立手动触发、通过飞书交接产物的 Agent：

1. 用户先用小红书采集工具把笔记采集到当前用户自己的“小红书选题库”。用户打开 Agent 1 后手动要求打标；Agent 1 自动扫描当前用户库中的未分析笔记，逐条执行“爆款素材加工打标”规则，并把原始字段与分析字段写入当前用户自己的飞书多维表格“爆款素材库”。用户不需要手动勾选笔记。默认不重新分析已有记录，只有用户明确提出历史重分析范围时才执行。
2. 用户打开 Agent 2，提供一个客户的定位会、启动会、补充资料、案例、评价、第三方资料或半成品资料。资料可以直接上传，也可以从当前用户已经授权的飞书中读取。Agent 2 通读全部资料，按“客户核心信息与人群画像提炼”规则生成完整画像卡，并写入该客户对应的飞书文档。
3. 用户打开 Agent 3，通过上传或飞书读取 Agent 1 的爆款素材库与 Agent 2 的客户画像卡，再按“选题规划”规则生成选题清单，并写入该客户对应的飞书文档。

每个有数 AI 用户的数据和飞书授权完全隔离；一个有数用户会服务很多客户。Agent 1 的爆款素材库属于用户级公共素材库，Agent 2/3 的产物属于该用户下的客户级文档。新客户创建新文档；同一客户再次运行时复用并更新原文档。

如果当前用户尚未连接飞书，Agent 在真实业务动作需要飞书时进入现有官方授权流程，授权成功后继续原任务。用户专属的客户名称、飞书文件名和链接不写死在 Agent Prompt，也不新增配置页面；Agent 优先从当前对话上下文获取，缺失时询问，再在当前用户自己的飞书中精确搜索、复用或创建目标。

业务规则以产品负责人提供的三个完整代码块 Prompt 为权威来源。统一契约需要补齐其中两处明确的上下文遗漏：Agent 1 输出增加“可借鉴部分”和“不可照搬部分”；Agent 3 每条选题输出增加“选择原因”。

## 业务目标
让非技术用户只需在对应 Agent 页面用自然语言发起任务，就能完成“采集素材 → 批量打标入飞书爆款库 → 提炼客户画像入飞书文档 → 结合两类产物生成客户选题并写回飞书”的完整链路；全过程保证当前用户隔离、客户隔离、来源可追溯、重复运行不制造重复数据，并允许上传文件作为飞书读取的替代输入路径。

## 优先级
高

## Triage
- 推荐轨道：Standard
- 分类理由：
  1. 数据库 schema 变更：当前不计划为客户或飞书目标新增内部配置表；S1 需核实 Agent 工具注册是否需要持久化变更
  2. 新增 API 端点：S1 需核实；至少需要新增 Agent 可调用的小红书选题库工具能力
  3. 新外部服务集成：否，复用现有小红书采集数据和飞书官方授权/执行链路
  4. 影响文件数：>3，涉及 Agent 工具、运行编排、飞书 Base/Doc 操作、提示词定义与端到端测试
  5. 高风险业务逻辑（支付/权限）：是，涉及多用户数据隔离、飞书授权和外部写入边界
- 人类决定：确认 Standard，并要求立即开始

## 范围内
- 三个 Agent 的统一数据契约、执行契约和上下游交接契约。
- Agent 1 对当前用户小红书选题库的分页读取，单页能力至少 100 条。
- Agent 1 自动识别未分析笔记、逐条分析、批量续跑和飞书 Base 幂等写入。
- Agent 2/3 的上传文件读取与当前用户飞书文件读取两条输入路径。
- 未授权飞书时沿用官方授权流程，授权后恢复原任务。
- 用户级爆款库与客户级画像/选题文档的精确搜索、创建、复用和更新。
- Prompt 业务规则、缺失信息处理、禁止事项、来源追溯及正式/待确认输出约束。
- 多用户隔离、同名文件歧义、部分失败、重试、重复运行和中断恢复验收。

## 范围外
- 新增客户管理页面、客户数据库实体或飞书目标配置页面。
- 要求用户在小红书选题库中手动勾选待分析笔记。
- 新增“重新分析”或“重新分析并覆盖未审核结果”按钮。
- Agent 1 生成选题或正文；Agent 2 生成选题/正文/口播稿；Agent 3 生成完整正文或口播稿。
- 跨用户共享小红书素材、飞书授权或客户文档。
- 本阶段自动发布小红书内容。

## 核心验收场景
1. 新用户无飞书授权时运行 Agent 1，完成授权后创建爆款素材库并继续写入，不要求重新发起任务。
2. Agent 1 可处理超过 100 条未分析笔记；再次运行不会产生重复记录；新增笔记后只处理新增内容。
3. 用户明确要求重分析指定历史范围时只处理该范围，不影响其他已有记录。
4. Agent 2 为新客户创建画像卡；为已有客户读取新资料后更新同一份画像卡。
5. Agent 3 可以分别通过上传和飞书获取两类上游产物；新客户创建选题文档，同一客户复用原文档。
6. Agent 3 严格执行达标来源、向内求/向外求、蓝 V、账号阶段、目标数量、参考链接和待确认规则。
7. 两个有数用户之间的小红书数据、飞书授权、Base 和 Doc 全部隔离。

## 备注
- “每次只分析一条”解释为 Agent 1 的原子分析单位是一条笔记；一次用户触发可以循环处理全部未分析笔记。
- Agent 1 的飞书 Base 是当前用户跨客户复用的公共弹药库；客户名称不是 Agent 1 的运行前提。
- Agent 2/3 在上下文没有客户名称时必须询问；搜索到多个同名目标时必须要求用户提供链接或选择，不能自行猜测。
- 同一客户的 Agent 2 画像卡维护完整最新版；同一客户的 Agent 3 选题文档按轮次留痕，用户明确要求修改某轮时更新指定轮次。
