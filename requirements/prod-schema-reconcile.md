# Dev → Prod 数据库增量兼容

## 来源
- 提出人：产品负责人
- 提出日期：2026-07-30

## 需求描述
将当前 Dev 已开发并运行的产品能力完整迁移到 Prod，包括首页 SOP、AI 问答助手、
AI 智能体、配置中心、选题库、插件/Skill、设置、通知中心、文档编辑和飞书连接。

Prod 已有客户长期使用，升级只能增加新功能需要的表、字段、索引和系统配置数据，
不得用 Dev 数据覆盖 Prod，也不得改变客户已有的个人资料、业务记录、积分余额、
积分流水或订阅原字段。

本需求只处理 Prod 数据库与后端新代码之间的兼容差异。QA 环境不在本次范围内。

## 业务目标
1. Prod 客户升级后可以使用 Dev 已验证的最新产品功能。
2. 新后端启动和运行时不会因 Prod 缺表、缺字段或缺模型路由而报错。
3. Prod 现有客户数据在升级前后保持不变；新增字段只保存新版本需要的新信息。
4. 数据库升级可重复演练、可核对、失败时可停止，不能靠“启动后自动试一遍”碰运气。

## 产品范围

### 本需求必须补齐
- 文档系统：新增 `document` 表，使智能体生成的 Markdown/TXT/DOCX 产物可以在线打开编辑。
- 飞书连接：新增个人飞书工作区所需的账号、授权会话、加密凭据和操作状态表。
- 智能体附件读取：给 `agent_attachment` 增加解析正文、摘要指纹、大小、页数和解析时间字段。
- 订阅新方案：给 `subscription` 增加 `plan_type` 和 `cycle_credits` 两个新字段。
- 图片理解：注册并启用 `qwen3.5-flash`，把附件图片理解任务切到该模型。
- 通知中心：确认现有 5 张通知/问卷表的唯一索引和外键完整，不覆盖已有公告或阅读记录。
- Skill 清理决策：保持官方模板库和“官方示例技能”已下线的产品状态；只允许删除项目自身的
  精确 seed 行，不允许按模糊条件删除客户 Skill。

### 明确保持关闭
- 会议副驾。
- 说话人分离。
- `chatbot_query_rewrite`。
- `universal_rewriter`。

### 由其他上线工作处理
- Sandbox 同机隔离、5 个最大并发任务。
- Prod API Key、加密主密钥和其他运行时密钥补齐与轮换。
- 前端通知中心/文档系统编译开关。

## 数据保护硬约束
- 禁止把 Dev 数据导入 Prod。
- 禁止 `DROP TABLE`、`TRUNCATE`、全表覆盖或重建现有业务表。
- 禁止修改 `user`、SOP、聊天、智能体历史、客户资料、订阅、试用积分、
  月订阅周期积分、加量包余额、会员事件、积分预扣、积分流水等原有值。
- `subscription` 现有 102 行只新增两个字段：
  - `plan_type='monthly'`
  - `cycle_credits=2000`
  这是为历史月度会员补充“方案名称”和“每周期积分”说明，不修改原来的开始时间、到期时间、
  购买月数、来源或任何积分记录。
- 新增文档/飞书表上线时必须为空；之后只保存用户在新版本中主动产生的数据。
- AI 服务、任务路由和定价行属于系统配置数据，可以按稳定唯一键幂等新增或切换；
  不得用自增 ID 猜测目标行。
- 所有 Prod 写操作前必须先做完整备份，并再次执行只读 preflight。
- 实际 Prod migration 与部署必须单独获得最终执行授权；本阶段只设计并在非 Prod 环境演练。

- [ ] migration 前后，受保护表的原字段逐表行数与校验值一致；积分三池
  `trial_grant`、`credit_cycle`、`user_booster_balance` 和会员事件
  `membership_event` 必须逐表纳入校验。
- [ ] 102 条历史订阅的原字段逐行校验值一致；两个新字段均为 `monthly/2000`。
- [ ] 文档和飞书新表存在、结构符合当前代码模型、初始行数为 0。
- [ ] 附件解析 5 个字段存在；Prod 当前 0 行附件无需回填。
- [ ] `qwen3.5-flash`、Ali DashScope route、`attachment.vision_describe` 和对应 pricing rule 唯一且启用。
- [ ] 旧 `qwen3-vl-flash` 路由停用但历史配置行保留。
- [ ] 通知中心唯一索引/外键核对通过。
- [ ] Dev 在应用 migration 后，会员余额、SOP、AI 问答、智能体、文档、通知和飞书 smoke test 通过。
- [ ] Prod 最终执行前生成备份标识、回滚/停止条件和逐项核对记录。

## 优先级
高

## Triage
- 推荐轨道：Standard
- 分类理由：
  1. 数据库 schema 变更：是
  2. 新增 API 端点：否
  3. 新外部服务集成：是（Prod 飞书运行时首次启用）
  4. 影响文件数：>3
  5. 高风险业务逻辑（支付/权限）：是（订阅/积分读链路）
- 人类决定：确认 Standard；用户已要求“全部按建议继续”，但 Prod 实际写入仍需最终单独授权。

## 备注
- 本需求不修改 `config_prod.yaml`。
- 会议相关表即使 Dev 存在，也不因本需求迁入 Prod，因为产品明确要求会议副驾和说话人分离保持关闭。
- Dev 与 Prod 都缺少最新订阅字段，因此 Dev 演练必须先补字段，再部署/验收当前后端。
