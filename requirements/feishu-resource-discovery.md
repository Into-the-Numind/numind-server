# 飞书资源发现与标题读取

## 来源
- 提出人：产品负责人
- 提出日期：2026-07-18

## 需求描述
平台允许用户搭建多个 Agent。任何 Agent 在当前登录用户提出飞书任务时，都应使用该用户长期保持的飞书连接；当新对话只给出飞书文档标题时，Agent 必须能先发现资源，再读取正文，而不是要求用户重新配置连接或提供 App ID/App Secret。

Dev 新对话 run 211 已复现：`lark-drive` 技能读取被平台拒绝，`drive +search` 与官方 `wiki +space-list` 又被命令目录拒绝，导致 Agent 在没有访问飞书的情况下误报“连接未就绪”。

## 业务目标
让所有用户自建 Agent 都具备一致的、按当前用户隔离的飞书资源发现能力，使“仅凭标题读取 Docs/Wiki/Base 资源”在新对话中可完成，并在权限不足时进入既有增量授权卡片流程。

## 优先级
高

## Triage
- 推荐轨道：Standard
- 分类理由：
  1. 数据库 schema 变更：否
  2. 新增 API 端点：否
  3. 新外部服务集成：否（扩展既有固定版本 lark-cli 能力）
  4. 影响文件数：>3
  5. 高风险业务逻辑（支付/权限）：是（扩大第三方命令与 scope 白名单）
- 人类决定：用户要求快速完成并授权全程自动化；按硬规则升级为 Standard。

## 备注
- 不把飞书连接绑定到 Agent；连接继续绑定当前登录用户。
- 本期只增加 Drive 只读标题搜索，不开放上传、移动、删除、复制、权限管理等写能力。
- IM 不在范围内。
