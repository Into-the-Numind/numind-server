# 周会员转年会员订阅修复 — 提案

## §1 方案概述 [客户可见]

年会员开通会显式写入月会员套餐和 2,000 积分。若客户仍处于有效周会员期，系统会拒绝把年会员直接叠加在周会员上，避免再次生成混合套餐；周会员到期后可正常开通年会员。

## §2 报价与周期 [客户可见]

- 预估工作量：紧急修复
- 报价：内部维护
- 交付时间线：本次生产数据校正后完成代码回归修复并按常规发布门禁上线

## §3 技术可行性 [AI 内部]

### 现有功能复用

- `GrantWeeklySubscription` 已拒绝有效月会员的反向混合开通。
- `GrantOrRenewSubscription` 可复用现有订阅校验、事务和审计写入。

### 技术风险

- 不能改写已完成的积分流水。
- 必须保持有效月会员续期、已过期周会员重新开通月会员的既有语义正确。

## §4 产品需求定义 — PRD [AI 内部]

### 用户故事

- 作为运营人员，我需要在客户的周会员已过期后开通年会员，使客户获得月会员和每周期 2,000 积分。
- 作为运营人员，我需要系统拒绝在有效周会员上直接叠加年会员，避免账务和套餐混合。

### 验收标准

- [ ] 有效周会员请求月/年会员时返回现有无效参数错误，订阅、积分周期和审计不发生写入。
- [ ] 已过期周会员重新开通月/年会员后，订阅的 `plan_type=monthly`、`cycle_credits=2000`。
- [ ] 新建月/年会员明确写入月会员和 2,000 积分，不依赖数据库默认值。
- [ ] 现有有效月会员续期仍按原锚点、月数和 2,000 积分执行。
- [ ] 复现测试先失败、修复后通过；后端完整测试和 lint 通过。

### 边界情况

- 有效周会员剩余任意时长：拒绝，不续期、不写事件。
- 已过期周会员：作为重新开通，月会员从本次开通时刻开始。
- 有效月会员：保持原续期逻辑。

### 权限规则

沿用现有 B2B 父账户为子账户开通会员的权限校验；不新增端点或权限。

### UI 行为规格

无 UI 改动；现有接口的错误响应会阻止无效混合开通。
