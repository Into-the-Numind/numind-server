# 飞书个人工作空间连接 — 提案

## §1 方案概述 [客户可见]

有数将把飞书变成每个用户 Agent 的长期个人工作空间。用户不需要手工填写 App ID、App Secret 或资源 ID；当用户要求 Agent 创建飞书文档、读取多维表格或使用知识库时，系统默认直接执行。只有系统已知未连接，或飞书明确返回未连接、权限不足、授权失效时，才进入个人自建应用创建或增量授权流程。

用户在飞书官方页面完成确认后，有数自动重试刚才的操作，无需用户重复指令。连接记录和原任务可跨后端重启保留；已失效的浏览器交互会话会重新生成。设置页只用于查看状态、重连和解绑，主要入口仍是 Agent 对话。

首版采用“现有有数 Agent + 确定性连接编排器 + lark-cli 适配器”，不新增独立飞书 Agent。本文所称“个人自建应用”统一指**每个有数用户独享一个飞书租户自建应用**，不是多人共享的有数应用。首版只支持有应用创建权，且本人可审批或能获得租户管理员审批的用户。

## §2 报价与周期 [客户可见]

- 预估工作量：10–15 个工程人日，包含后端、前端、自动化测试和一次真实飞书租户 E2E
- 报价：内部产品开发，不单独报价
- 交付时间线：S2 技术设计确认后约 2–3 周完成开发、自动验收和 dev 人工验收；生产部署需另行确认

## §3 技术可行性 [AI 内部]

### 现有功能复用

- 复用现有 `FeishuCLIRunner`、每用户 CLI HOME 隔离思路和 lark-cli 安装链路，但 CLI HOME 不再作为产品连接状态的唯一来源。
- 复用现有 `feishu_connect`、文档创建、多维表格读取 Agent 工具的协议和 UI 授权提示，统一接入新的连接编排器。
- 复用 `user_third_party_account` 作为账号归属基础；S2 决定扩表还是新增连接、授权会话、待重试操作表。
- 复用设置页飞书入口，收敛为状态、权限概览、重连、解绑四类行为。
- 复用现有 Agent run/tool call 标识，建立待重试操作与原任务的关联。

### 技术风险

- **lark-cli 作为外部执行层**：版本和 JSON 输出可能变化。缓解：固定版本、白名单 argv、严格 JSON 解析、超时/输出上限、错误分类和 adapter contract tests。
- **长期凭据安全**：现有部署可能递归设置 `775`。缓解：每用户目录 `0700`、敏感文件最小权限、静态加密或受控密钥存储、日志脱敏，禁止把密钥写入 DB 明文字段。
- **多实例并发与重复执行**：内存锁不能跨 runner。缓解：数据库幂等键、持久化状态转换、分布式/数据库锁和可靠的待重试队列。
- **授权不是单一步骤**：应用权限审批、用户授权和真实操作结果可能不同步。缓解：按飞书结构化错误推进对应步骤；不做逐次权限预检，配置后以原操作重试结果为准。
- **应用创建是浏览器交互流程**：命令可能阻塞或链接过期。缓解：拆成可持久化的授权会话，记录步骤与过期时间，过期后重新生成，不复用旧 device code。
- **建应用进程无法原样跨重启**：`config init --new` 的阻塞进程消失后，旧链接不能被视为可恢复。缓解：持久化原操作和当前阶段；重启后若 CLI HOME 已出现有效应用则继续，否则废弃旧会话并生成新链接，前端状态卡同步替换。
- **创建文档的结果可能不确定**：请求到达飞书但响应丢失时，盲目重试可能生成重复文档。缓解：只对结构化、明确未产生副作用的权限错误自动重试；操作进入 `unknown` 时停止自动重试并引导用户核对。
- **资源定位困难**：用户通常提供飞书 URL 或自然语言，不会提供 opaque token。缓解：首版工具优先接受并解析飞书 URL；自然语言搜索能力按真实 API 可行性在 S2 定义。
- **解绑不彻底**：只删 DB 行会遗留 CLI HOME 和 Token。缓解：解绑必须删除有数侧所有凭据、CLI HOME、授权会话和待重试操作，并清晰告知远端自建应用是否仍保留。

### AI 可观测性（如功能涉及 LLM 调用）

## §4 产品需求定义 — PRD [AI 内部 — 不要为可读性简化]

### 4.1 目标用户与准入条件

- 目标用户：希望让有数 Agent 直接使用自己飞书工作空间的有数用户。
- 首版准入：用户有权创建一个自己独享的飞书租户自建应用，并且本人可审批或能获得租户管理员批准所需应用权限。
- 不满足准入条件时：有数明确说明受阻步骤和需要的管理员动作，不伪装为普通授权失败，不自动切换到共享应用。

### 4.2 用户故事

- 作为有数用户，我提出飞书操作后，希望 Agent 先直接尝试执行，成功时不出现额外权限检查或确认。
- 作为尚未连接飞书的用户，我希望 Agent 自动发起每用户独享的飞书租户自建应用创建，只让我在飞书官方页面确认。
- 作为缺少某项飞书权限的用户，我希望只申请当前操作需要的最小权限，而不是一次索取全部权限。
- 作为正在等待管理员审批的用户，我希望明确看到“等待管理员批准”，而不是笼统的“授权中”。
- 作为刚完成配置的用户，我希望有数自动重试刚才的操作，不需要重复输入需求。
- 作为已连接用户，我希望后端重启后仍能继续使用飞书，不需要重新连接。
- 作为用户，我希望用飞书 URL 指定多维表格和知识库资源，不需要寻找内部 token。
- 作为用户，我希望解绑后有数侧不再保留或使用我的飞书凭据。

### 4.3 首版能力范围

- 每用户独享的飞书租户自建应用创建与持久连接。
- 按能力增量授权：文档、多维表格、知识库。
- 将 Agent 结果创建为飞书文档并返回可访问链接。
- 读取用户通过 URL 指定的多维表格及目标数据表内容。
- 读取用户通过 URL 指定的知识库节点内容；知识库全局搜索是否可行由 S2 按官方 API 能力确认。
- 设置页展示真实连接状态、最近已知能力状态、重连和解绑入口。

### 4.4 核心交互流程

1. 用户向现有有数 Agent 发出飞书操作指令。
2. 若系统已明确知道用户未连接，直接发起创建该用户独享的飞书租户自建应用；否则直接尝试原飞书操作，不进行强制权限预检。
3. 操作成功：返回结果或资源链接，更新最近成功状态。
4. 飞书明确返回未连接、缺权限或授权失效，且错误语义能够确认原操作没有产生副作用：连接编排器持久化原操作和幂等键，进入对应配置步骤。
5. 前端展示飞书官方链接和二维码，并明确当前等待的是用户确认还是管理员批准。
6. 用户完成配置后，系统自动、幂等地重试原操作。编排器直接重放已持久化的 tool、规范化参数和上下文，不让模型重新生成参数。
7. 重试成功：保存结果并回填原对话；重试仍缺权限：展示准确的下一步，不循环授权；其他失败：按真实错误提示，不误报为权限问题。
8. 写操作执行结果不确定：标记为 `unknown`，禁止自动重试，提示用户核对可能已生成的资源后再决定。

### 4.5 验收标准

- [ ] 一个从未连接的真实用户可在 Agent 对话中触发自己独享的飞书租户自建应用创建，全程不手工复制 App ID/App Secret。
- [ ] 用户完成飞书官方页面确认后，系统自动完成原操作；用户无需重复输入指令。
- [ ] 已连接且权限充足时，飞书操作直接执行，链路中没有额外的阻塞式权限检查请求。
- [ ] 首次使用文档、多维表格、知识库时只申请对应能力所需的最小权限，后续授权可累积。
- [ ] 产品能区分并展示：创建应用、等待管理员批准、等待用户授权、链接过期、用户拒绝、授权撤销、普通执行错误。
- [ ] 配置完成后的原操作最多产生一次业务副作用；重复回调、重复轮询、多实例并发不会创建重复文档。
- [ ] 待执行操作至少区分 `not_started → executing → succeeded | failed | unknown`；只有明确未产生副作用的权限错误允许进入授权后自动重试。
- [ ] 后端重启和 runner 实例切换后，连接状态和待重试操作仍可继续。
- [ ] 分别在建应用、等待管理员审批、等待用户授权三个阶段重启后端：原操作不丢失；已完成的应用状态继续推进，失效的浏览器会话生成新链接并替换旧状态卡。
- [ ] 两个用户并发连接时，应用、凭据、CLI HOME、授权状态和操作结果完全隔离。
- [ ] Agent 能创建飞书文档并返回用户可访问的链接。
- [ ] Agent 能通过飞书 URL 读取一个真实多维表格的数据。
- [ ] Agent 能通过飞书 URL 读取一个真实知识库节点内容。
- [ ] 授权被用户撤销后，下一次相关操作能识别失效并发起重新配置，不静默失败。
- [ ] 解绑会删除 DB 中的凭据引用和控制状态、受保护 CLI HOME 中的密钥材料、活动授权会话及未执行待重试操作；解绑后调用无法继续访问飞书。
- [ ] 所有凭据目录和敏感文件权限满足最小权限要求，部署脚本不会将其递归放宽到 `775`。
- [ ] 至少完成一次真实租户 E2E：连接 → 创建文档 → 读 Base → 读 Wiki → 后端重启后再次执行 → 撤销后重连 → 解绑。
- [ ] S2 结束前使用固定 lark-cli 版本完成真实 spike：记录 Doc/Base/Wiki 最小 scope、管理员审批状态、用户授权状态和主要错误 JSON；无法稳定分类时必须收窄 UI 承诺或调整 adapter 控制面。

### 4.6 边界情况

- 用户无权创建自建应用；管理员拒绝或长时间不审批。
- 用户或租户的自建应用配额已耗尽。
- 用户拒绝授权、关闭页面、授权链接或 device code 过期。
- 应用权限已批准但用户权限缺失，或用户已授权但应用权限尚未批准。
- 用户在多个浏览器标签或多台设备重复发起同一连接。
- 同一用户同时触发多个需要不同权限的飞书操作。
- lark-cli 超时、崩溃、输出非 JSON、版本不兼容或升级中断。
- 飞书返回限流、临时网络错误、资源不存在、用户无资源访问权等非授权错误。
- 写操作请求已到达飞书但响应丢失，结果不确定；不得盲目重试造成重复文档。
- 用户提供错误、过期、无权限或不受支持类型的飞书 URL。
- 用户解绑时仍有执行中或待重试操作。

### 4.7 权限规则

- 飞书能力对所有具备 Agent 使用资格的有数用户开放，但首版必须满足飞书侧自建应用/管理员审批准入条件。
- 一个有数用户只能访问自己的飞书连接和凭据；服务端从登录身份解析 `user_id`，不接受客户端指定其他用户。
- 默认直接尝试执行；缓存的权限状态只用于展示、错误解释和避免已知未连接时的无效调用。
- 新能力首次缺权限时按具体 scope 增量授权；禁止默认申请 `all` 域。
- 高风险飞书写操作仍遵循 Agent 通用高风险确认规则；本需求中的“授权后自动执行”不等于绕过删除、批量修改等高风险确认。

### 4.8 UI 行为规格

- 页面位置：Agent 对话为主入口；个人设置 > 第三方连接 > 飞书为辅助入口。
- 布局要求：对话中使用可恢复的授权状态卡；设置页使用单一连接卡展示账号、状态、能力概览和操作入口。
- 交互模式：展示飞书官方原始链接及二维码；链接不可改写。用户完成后系统自动推进，也提供“我已完成”作为主动刷新入口。
- Loading：明确显示当前步骤，不使用无限转圈；后台轮询有截止时间。
- Empty：设置页说明可直接在 Agent 中提出飞书任务开始连接。
- Error：按创建权限、管理员审批、用户拒绝、链接过期、授权撤销、CLI/网络异常分类给出下一步。
- Success：自动回到原 Agent 任务并展示最终飞书结果；设置页同步为已连接。

### 4.9 非目标

- 首版不提供有数共享飞书应用、应用商店安装或普通员工通用接入路径。
- 首版不新增独立飞书 Agent。
- 首版不提供任意 lark-cli 命令透传。
- 首版不扩展飞书消息发送、日历、邮箱、审批等能力。
- 首版不修复或合并旧的 monitor webhook 集成；该路径保持隔离，安全问题另立需求处理。
- 首版不提供独立的文档读取/更新工具；“写成飞书文档”只包含创建带完整内容的新文档。后续读写另立范围。
- 首版不把所有运行时操作整体改写成 Go 直连 OpenAPI，但 adapter 必须允许未来逐步迁移。

### 4.10 S2 待锁定问题

- 连接、授权会话、待重试操作的数据表拆分和状态转换。
- SOT 分工：DB 保存连接、会话、待执行操作和凭据引用；受保护的 CLI HOME 保存 adapter 所需密钥材料；真实操作结果高于权限缓存。S2 锁定 CLI HOME 静态加密、运行时解封和密钥管理方案。
- 多实例锁、可靠队列/outbox 与 Agent run 恢复接口。
- 知识库搜索能力和飞书 URL 解析契约。
- 固定的 lark-cli 版本、升级策略及 adapter 输入输出契约。

### 4.11 S2 前置 Gate

- 必须准备一个有应用创建权、且可获得管理员审批的真实飞书账号。
- 必须准备一个可读 Base URL 和一个可读 Wiki URL。
- 必须在固定 lark-cli 版本上完成最小 scope、错误分类和三阶段重启 spike；未通过时不得批准 S2 设计。
