# 飞书创建个人应用完成态修复 — 提案

## §1 方案概述

修复有数把飞书“创建个人应用”完成后误报为服务错误的问题。服务将继续严格控制可执行命令，但不再要求该命令输出不存在的 JSON 回执；它会在命令成功退出后，使用已有的加密工作目录校验完整应用配置。对于这次误判留下的失败卡，只允许当前任务正在绑定的那一张重试。

## §2 交付范围

- 不新增页面、接口、数据库字段或飞书权限。
- 保留原有用户、飞书账号代际、原任务、授权阶段、权限范围和活动租约围栏。
- 用户仍在飞书官方页面完成创建；有数不保存临时链接、设备码或应用密钥。

## §3 技术可行性

### 现有功能复用

- `ControlledLarkCLIRunner` 已限制命令和进程生命周期。
- `AppIDFromHome` 已验证临时工作目录中完整的应用配置。
- 授权会话替换已在事务中重绑任务摘要并保留租约围栏。

### 技术风险与缓解

- 风险：把任意非 JSON 输出当成功。缓解：仅对严格白名单的 `config init --new` 放宽文本回执；进程退出、输出限制、URL 校验及后续完整应用配置校验全部保持。
- 风险：失败会话被任意重试。缓解：只接受任务摘要精确绑定的失败源会话；保留用户、代际、任务、阶段、权限范围和活动租约检查。

### 涉及仓库

- [x] numind-server
- [ ] numind-web-v3
- [ ] numind-admin-web

### AI 可观测性

不涉及新增 LLM 调用。

## §4 PRD

### 用户故事

- 作为完成了飞书官方创建流程的用户，我需要返回有数后能继续任务，而不是看到服务错误。
- 作为持有一张因系统误判而失败的当前授权卡的用户，我需要能重新生成链接，而不必重开整个任务。

### 验收标准

- [ ] `config init --new` 正常退出并写入完整应用配置时，不因非 JSON 标准输出而失败。
- [ ] 创建成功仍必须通过已有应用配置校验；普通授权命令仍要求其 JSON 成功回执。
- [ ] 当前任务精确绑定的失败创建应用会话可生成替代会话并继续；其他失败/跨任务/跨用户/活动租约情形仍拒绝。
- [ ] 回归测试先失败、修复后通过，并完成后端 lint 与完整测试。

### 边界情况

- 命令退出异常、输出超限、URL 非法或应用配置不完整时，仍判定失败。
- 同一任务存在活动且未过期的替代会话时，拒绝再生成链接。

### 权限规则

仅登录用户对自己的等待中任务操作；不增加飞书权限。
