# Agent 运行界面精简与真实停止 — 提案

## §1 方案概述 [客户可见]

本次将 Agent 运行页收拢为更少、更可信的操作：输入框不再显示预计积分消耗；欢迎区去掉“🤖 + Agent 名称”标签；运行时不再在顶部重复提供“取消任务”。

输入框右侧的方形停止键保留为唯一停止入口，但它的含义将变成真正停止：前端立即中断 SSE，同时向现有服务发送取消请求，并在成功后将当前 run 标为已取消。这样用户看到的停止操作与后台执行状态一致。

消息区的“新内容”提示会改成一个仅含向下箭头的圆形按钮；其可访问名称仍为“回到底部”，保留键盘与屏幕阅读器可用性。

## §3 技术可行性 [AI 内部]

### 现有功能复用

- `AgentInputArea.vue` 已具备运行时切换为方形停止键的 UI。
- `useAgentStream.stop()` 已可通过 `AbortController` 终止客户端 SSE。
- `AgentChatStore.cancelCurrent()` 已封装现有取消接口，并将 run 更新为 `cancelled`。
- `AgentChatView.vue` 已拥有顶部取消任务的完整调用链，可提炼为输入区停止处理器。
- `AgentMessageList.vue` 已有“回到底部”的交互、`aria-label` 与滚动处理，只需调整呈现。

### 技术风险

1. **假停止风险**：仅中断 SSE 时，服务器仍可能继续运行。缓解：唯一停止处理器必须先终止流，再调用 `cancelCurrent()`，并以 Playwright 断言取消请求与 `cancelled` 状态。
2. **重复或无 run 的取消请求**：SSE 首帧到达前可能尚未得到 run。缓解：保留 store 的 `currentRun` guard；测试已启动的 run，且 UI 在 stop 后立即不可重复触发。
3. **遗留测试与选择器漂移**：现有 streaming E2E 仍引用已删除的 `.abort-bar`。缓解：在 RED 测试阶段更新为实际 `.send-btn--stop` 控件，并断言取消 API，不只断言输入恢复。
4. **视觉精简损害可发现性**：移除“新内容”文本会降低含义表达。缓解：保留语义 `aria-label="回到底部"`、可见 focus ring 与圆形箭头按钮。

## §4 产品需求定义 — PRD [AI 内部]

### 用户故事

- 作为正在向 Agent 提问的用户，我不需要在输入时看到预计积分消耗，以便专注完成任务。
- 作为首次打开新对话的用户，我只看到欢迎语和输入入口，而不是重复的 Agent 身份标签。
- 作为运行中任务的用户，我在输入框按下停止键后，后台任务确实停止，且不需要在顶部寻找第二个取消入口。
- 作为正在阅读历史消息的用户，我能用紧凑的圆形向下箭头回到最新消息。

### 验收标准

- [ ] 任意非空输入下，DOM 与可见文字均不含“预计消耗”或“积分”预估栏；不再请求预估接口。
- [ ] 新会话欢迎区不渲染 `first-run__identity`、emoji 或 Agent 名称标签；欢迎语本身保持。
- [ ] `AgentChatHeader` 不再渲染、接收或触发“取消任务”控制。
- [ ] 流式运行中，输入框停止键可点击；点击后浏览器 SSE 被终止，且对当前 `run_id` 发出一次 `POST /v1/agent-runs/:id/cancel`。
- [ ] 取消成功后，当前 run 状态为 `cancelled`，输入框恢复可编辑；不展示“发送失败”。
- [ ] 消息滚动被用户打断时，“新内容”文字不渲染；回到底部按钮仅显示圆形箭头，保留 `aria-label="回到底部"`、键盘可聚焦和 hover/focus 状态。
- [ ] `npm run lint`、`npm run type-check` 与覆盖本需求的 Playwright 测试均通过。

### 边界情况

- 没有当前 run 或 run 已结束时，不发送取消请求。
- 取消请求失败时，停止键不能静默伪造 `cancelled` 状态；保留现有错误反馈与真实 store 状态。
- 历史只读会话不显示输入区，也不暴露停止入口。
- 窄屏下圆形“回到底部”按钮不遮挡输入区域，也不产生横向滚动。

### 权限规则

- 复用现有 Agent run 所有权与取消 API 的权限校验；不新增角色、套餐或权限规则。

### UI 行为规格

- 页面位置：用户端 `/agent/chat/:sessionId`。
- 布局要求：保留现有 Agent 对话布局和设计 token；只移除重复信息与控件。
- 交互模式：运行中发送按钮替换为方形停止按钮；停止成功后恢复发送按钮。回到底部按钮为圆形箭头。
- 状态处理：运行中停止按钮可用；取消中的真实状态来自 store；取消失败显示既有通知，成功显示既有已取消系统消息。
