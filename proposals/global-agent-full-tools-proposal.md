# 全 Agent 默认开放平台工具——产品方案

## 决策

把“Agent 能用哪些平台工具”的单一真相源从每条 AgentDefinition 的 `tool_flags`，迁移为服务端平台注册表：运行时枚举全部已注册工具，只排除工具自身明确硬禁用的项。当前唯一硬禁用项是 `document_generate`。

## 为什么这样做

只修改三个官方 Agent 的清单无法覆盖用户已有 Agent 和未来新建 Agent；只把默认开关改成 true 也无法修复历史数据中的 false。必须在所有运行路径共同使用的工具选择层收口，才能保证默认行为稳定。

## 兼容策略

- 保留 `tool_flags` 字段和现有请求结构，不做破坏性 schema/API 变更。
- `ToolNames`、`EnforceToolAllowlist` 和分类键继续可被旧代码读写，但运行时不再据此缩减工具。
- 权限流水线中的 ToolFlag 验证器保留 ID 和挂载位置，但改为兼容性透传，避免旧 Agent 在执行阶段被二次拒绝。
- 三个官方 Agent 的清单同步为“全 true、仅 `document_generate=false`”，方便审计和后续导入，但运行时安全不依赖这份清单。

## 技能边界

平台镜像内 `skills/` 只注册四个文件生产技能，它们通过统一目录进入所有 Agent：

- `xlsx-author`
- `docx-author`
- `pptx-author`
- `pdf-from-html`

租户自建和市场技能来自数据库，只从当前 Agent 已绑定技能构造 `SkillByName`；本次不改变这条边界。

## 安全不变量

“工具可见”不等于“无限制执行”。每个工具仍执行自身输入校验和权限检查，平台权限链仍处理租户、管理员规则、路径/资源归属、外部授权和高风险确认；沙箱、并发、积分等运行约束不变。

## 发布与回滚

先以测试锁定统一选择语义，再更新官方清单。Dev 部署后验证服务健康和真实 AgentDefinition 的可用工具集合。若需回滚，只回滚该服务提交；数据库无需回滚。
