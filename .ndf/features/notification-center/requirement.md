# 通知系统（公告 + 已读未读 + 问卷调查）— Notification Center

## 来源
- 提出人：产品负责人（用户）
- 提出日期：2026-06-16

## 需求描述
（客户原话）"我需要你帮我开发一套通知系统，就是我能够发官方公告，用户能够看到，分为已读和未读，还要有问卷调查的功能，这样方便做用户调研。这套系统需要能和别的部分能够很好的区分开，这样才不会影响 prod 打 tag 部署。开发过程一定要用 worktree。"

结构化：
1. **官方公告发布**：管理端（admin）可发布官方公告，用户端（web-v3）可看到。
2. **已读 / 未读**：用户端区分公告的已读/未读状态（铃铛红点）。
3. **问卷调查**：公告可以是"问卷"类型，用于用户调研，支持单选/多选/评分/开放文本四种题型。
4. **后台已读统计**：发布者需在 admin 端看到每条公告的已读率 + 已读/未读用户明细（问卷另含回收率）。
5. **强隔离**：与现有功能解耦，不影响 prod 打 tag 部署（feature flag 默认关闭 + 独立表 + 独立路由 + 懒加载前端）。

## 业务目标
- 建立官方 → 用户的单向触达通道（产品公告、运营通知）。
- 通过问卷把"触达"升级为"调研"，低成本收集结构化用户反馈（N=1 莫小派阶段做用户洞察的基础设施）。
- 已读统计 + 回收率让运营/产品能量化触达效果与样本量。

## 优先级
中（非阻塞线上业务，但为用户调研提供长期基础设施）

## 锁定的产品决策（2026-06-16 AskUserQuestion 确认）
| 维度 | 结论 |
|------|------|
| 展示形态 | 用户端顶部**铃铛 + 未读红点**，点开进**通知中心**列表 |
| 受众 | **仅全员广播**（V1 不做定向；数据模型留 audience 扩展位） |
| 问卷题型 | 单选 / 多选 / 评分（星级或 NPS）/ 开放文本 —— **四种全做** |
| 已读统计 | 后台要**已读率 + 已读/未读用户明细**；问卷额外要**回收率 + 答卷明细** |
| 读/未读 | 用户端区分（用户首次拉取/打开即记已读回执） |

## AI 自主拍板的设计决策
1. **问卷 = 公告的一种 type**：`announcement.type ∈ {plain, survey}`，共用通知中心、广播、已读回执；survey 额外挂题目与答卷。
2. **正文 Markdown 渲染**（复用前端既有 markdown 渲染），不做富文本编辑器。
3. **可选过期时间**：公告可设 `expires_at`，过期后用户端不再展示；V1 不做定时发布（发布即生效）。
4. **一人一答**：每用户每问卷仅一份答卷（唯一约束），后台可聚合可下钻。
5. **隔离方案**：feature flag（后端 config key 代码默认 OFF + 前端 flag 默认隐藏）+ 全新独立表 + 独立路由组 `/v1/announcements`、`/v1/admin/announcements`，零改动现有表/端点。

## Triage
- 推荐轨道：**Standard**
- 分类理由：
  1. 数据库 schema 变更：**是**（公告、已读回执、问卷题目、答卷等新表）
  2. 新增 API 端点：**是**（admin 发布/统计 + 用户拉取/标记已读/提交问卷）
  3. 新外部服务集成：否
  4. 影响文件数：**>3**（跨 numind-server / numind-admin-web / numind-web-v3 三仓库）
  5. 高风险业务逻辑（支付/权限）：部分（admin 鉴权 + 用户鉴权，无支付）
- 人类决定：**确认 Standard**（用户 2026-06-16 授权直接开工，autopilot 推进，不部署 prod）
