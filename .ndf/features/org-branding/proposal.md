# 机构自定义品牌名（org-branding）— 提案

## §1 方案概述 [客户可见]

让每个机构客户在产品里看到**自己的公司名称**，而不是统一的工具品牌。

- 机构管理者（B 端父账户）在「设置」页填一个"公司名称"，保存后：
  - 自己的项目左上角立刻显示这个公司名；
  - 这个机构下面所有员工/学员（C 端子账户）登录后，左上角也都显示同一个公司名；
- 没填名称时，左上角统一显示 **"有数AI"**（产品默认门面）。
- 登录页（用户端 + 管理端）把旧的图片 logo 换成 **"有数AI"** 文字，门面统一。

效果：交付给机构客户时更有"这是我们自己的系统"的感觉（白标第一步），同时把历史遗留的"莫小派"图片门面收敛到"有数AI"品牌。

## §3 技术可行性 [AI 内部]

### 现有功能复用
- **数据模型**：`User` 表已有 `ParentUserID *uint`（null=机构父账户），B2B2C 父子关系现成，无需新表，只加一个 `company_name` 字段。
- **接口**：复用现有 `PUT /v1/users/me`（`UpdateProfile`）和 `GET /v1/users/me`（`GetCurrentUser`），各加一个字段即可，不新建端点。
- **前端用户态**：`useUserStore` 已有 `parent_user_id` 和 `isParentUser` computed，前端按它决定是否显示编辑框 + 解析展示名。
- **侧边栏**：`AppSidebar.vue` 当前是文字渲染（硬编码 `靓靓·海外IP研究所`），改成读 store 派生值即可，无结构改造。

### 技术风险
- **风险 1：GORM `default` / 零值更新坑**。`company_name` 是普通 string，无 `default:true` bool 问题；但更新走 `UpdateUser`（`db.Save`-style）要确认空字符串能清空（用户想删名称回到"有数AI"）。缓解：用指针 `*string` 区分"未传"vs"传空串"，biz 层显式赋值；加回归测试覆盖"设空串→兜底有数AI"。
- **风险 2：子账户误改**。子账户也调 `PUT /v1/users/me`，若不守卫会让子账户把自己 company_name 写进去（虽然 GET 时按父账户解析会忽略，但脏数据）。缓解：biz 层守卫——`ParentUserID != nil` 时拒绝/忽略 company_name 字段；前端对子账户隐藏编辑框。
- **风险 3：GET /me 解析父账户名要多查一次库**。缓解：仅当 `ParentUserID != nil` 时按父 ID 查一次（Preload Parent 或单查），单用户接口可接受；不引入 N+1（非列表接口）。
- **风险 4：migration 不随 CI 自动跑**（见 [[project_dev_deploy_migration_gap]]）。缓解：S6 ndf-done 后手工 SSH 到 dev 跑 migration；字段也靠 GORM AutoMigrate 兜底（dev 重启会建列），但仍以 migration SQL 为准。

## §4 产品需求定义 — PRD [AI 内部]

### 用户故事
- **US1**：作为机构父账户管理者，我需要在「设置」里填写公司名称，以便我和我机构下的所有成员在左上角看到自己的品牌名。
- **US2**：作为机构下的 C 端子账户用户，我登录后左上角自动显示我所属机构的公司名称（不需要也不能自己改）。
- **US3**：作为任意未设置公司名称的用户，我看到左上角显示"有数AI"（默认门面）。
- **US4**：作为任意访客，我在登录页看到"有数AI"文字 logo（用户端和管理端登录页一致）。

### 验收标准
- [ ] AC1：父账户在设置页输入"XX公司"并保存后，刷新页面左上角侧边栏显示"XX公司"。
- [ ] AC2：该父账户下的子账户登录后，左上角侧边栏显示同一个"XX公司"。
- [ ] AC3：父账户把公司名清空保存后，自己和子账户左上角都回退显示"有数AI"。
- [ ] AC4：从未设置公司名的账户，左上角显示"有数AI"。
- [ ] AC5：子账户的设置页**看不到**公司名编辑框（只有父账户能编辑）。
- [ ] AC6：子账户即使直接调 `PUT /v1/users/me` 带 company_name，也不会改变其继承的展示名（后端守卫）。
- [ ] AC7：用户端登录页显示"有数AI"文字（不再是莫小派图片）。
- [ ] AC8：管理端登录页显示"有数AI"文字（不再是"N"方块）。
- [ ] AC9：`GET /v1/users/me` 响应含 `company_name` 字段，值为该用户的有效品牌名（父用自己/子用父账户/空则空串）。

### 边界情况
- 空字符串 / 仅空格：trim 后为空视为"未设置"，展示兜底"有数AI"。
- 超长名称：限制最大长度（拟 100 字符，与 nickname 一致），超长拒绝并提示。
- 子账户调用更新接口带 company_name：后端忽略该字段（不报错，静默 drop），保证继承语义。
- 父账户改名后子账户**下次拉取 /me 时**生效（不需要实时推送；前端每次进入应用拉一次 /me）。

### 权限规则
- 仅 `credits` 体系所有用户（即全部用户）；不区分会员等级（展示型）。
- **编辑权限**：仅父账户（`parent_user_id == null`）可写 company_name；子账户只读继承。
- 用户端功能；管理端**不加**设置入口（本次只改管理端登录页 logo）。

### UI 行为规格
- **设置页**（`web-v3/SettingsView.vue`，仅父账户可见）：
  - 位置：现有资料区内新增"公司名称"一项，带输入框 + 保存。
  - 交互：blur 时校验（非每次 keystroke，见 ui-ux 硬规则），保存调 `PUT /v1/users/me`。
  - 状态：保存中 loading；成功 toast；失败读 message 提示。
- **侧边栏**（`web-v3/AppSidebar.vue`）：
  - 展示派生值 `displayBrandName = effectiveCompanyName || "有数AI"`。
  - 折叠态/展开态都正确显示（折叠态可只显首字或保持现有 logo-mark 逻辑）。
- **登录页**（`web-v3/LoginView.vue` + `admin-web/LoginView.vue`）：
  - 把图片/字符方块替换为"有数AI"文字标题，沿用现有排版位置（见 [[feedback_bp_minimal_diff]] 精神：最小改动，不重设计）。
