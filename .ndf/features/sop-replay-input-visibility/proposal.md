# SOP 回看页输入与上传可见 — 提案

## §1 方案概述 [客户可见]
当用户回看一次历史 SOP 运行时，每一步将不再只显示 AI 的产出，而是完整呈现**当时这一步的输入上下文**：

- **你的输入**：那一步用户亲手写的文字，原样可读。
- **上传的素材**：当时上传的图片直接显示缩略图（点击放大查看），文档/PDF 显示为带图标的文件卡片（点击在新标签打开/下载）。
- **（可展开）系统读取到的文本**：每个文件下方可展开查看系统当时从该文件提取并喂给 AI 的文本，便于精确复盘"AI 到底看到了什么"。

呈现位置紧贴该步的输出之上，只读、美观，与现有产品视觉统一。这样教练和学员复盘历史运行时，能一眼看清"当时喂了什么 → AI 产出了什么"，让历史结果完全可追溯。

## §3 技术可行性 [AI 内部]
### 现有功能复用
- **数据已全部持久化**：`sop_node_run.input`（用户输入合并文本）+ `sop_file` 表（`file_url`/`object_key`/`file_name`/`file_type`/`file_size`/`content`，含 `run_id`+`node_id`）。无需建表/加列/迁移。
- **store 层已有**：`Sop().ListFilesByRun(runID)`、`ListFilesByNodeRuns(nodeIDs)`。
- **COS 重签名已有**：`util.GenerateSignedURL(ctx, objectKey, expirySeconds)`（method-bound GET presign）。
- **前端上传展示组件已有**：`components/StepInput.vue` / `InputCard.vue` 的文件 chip 样式、`OutputCard.vue` 的只读卡片布局与设计 token，可作为新只读输入卡的视觉基准。
- **既有接口已有 files 字段先例**：`GET /sop/templates/:id/runs` 的 `TemplateNodeRunInfo` 已含 `files`，复用其 `TemplateFileInfo` DTO 形态即可保持一致。

### 技术风险
1. **【高】COS 私有桶裸链 403**。`UploadBytesToCOS` 存的是非签名 base URL（`cos_uploader.go:113`），而桶私有（`cos-url-lazy-resign` hotfix 已证匿名 GET 被拒）。直接把 `file_url` 透给前端 = 可见的死链。
   - 缓解：后端在 `GetRunStatus` 内对每个文件用 `object_key` 实时 `GenerateSignedURL`（GET inline，过期 2h），图片可 `<img>` 内联渲染、文档点击新标签打开。`object_key` 为空或签名失败 → 回退原 `file_url`（优雅降级，不阻断）。
2. **【中】`input` 是合并 blob**。执行时把每个文件提取文本以 `=== 文件名 ===\n内容` 追加到用户文本后（`controller sop.go:717-748`）；用户纯文本未单独持久化。直接整块渲染会与文件卡内容重复且杂乱。
   - 缓解：前端用已知文件名列表，从 `input` 中剥离 `=== <filename> ===\n...` 段与 `用户已上传以下文件：...` 提示段，仅展示用户文本；剥离后为空则隐藏文本块或显示"（本步仅上传文件，无文本输入）"。剥离是纯展示层处理，不改 `input` 语义（其他消费方不受影响）。
3. **【低】回看态状态判定**。需在 `SopStepView` 的 `done-history` 与 `done-current` 只读态都渲染输入卡（这两态都是"看一个已完成步骤"）。正在执行的 input 态已有 InputCard，不动。
4. **【低】历史数据无 files**。早期运行可能没有 `sop_file` 记录或 `object_key`——files 为空时不渲染上传区，仅展示文本，无报错。

## §4 产品需求定义 — PRD [AI 内部 — 不要为可读性简化]
### 用户故事
- 作为复盘历史运行的用户，我需要在回看每一步时看到**当时我输入的文字**，以便回忆这一步给了 AI 什么指令。
- 作为复盘历史运行的用户，我需要看到**当时上传的图片/文档**（图片可预览、文档可打开），以便核对喂给这一步的素材。
- 作为深度复盘的用户，我需要可选地查看**系统从文件中提取的文本**，以便精确理解 AI 实际读到的内容。

### 验收标准
- [ ] AC1：进入历史运行回看页（`/sop/run?runId=X`），点开任一已完成步骤，能看到该步「你的输入」文本块（若该步有文本输入）。
- [ ] AC2：若该步当时上传过图片，回看时图片以缩略图渲染且可点击放大/打开；链接为后端实时签名链接，**实际可加载成功（非 403 死链）**。
- [ ] AC3：若该步当时上传过文档/PDF 等非图片文件，回看时显示文件卡片（文件名 + 类型/大小 + 打开入口），点击可在新标签打开/下载。
- [ ] AC4：`input` 中由文件合并进来的 `=== 文件名 ===` 提取文本不在「你的输入」文本块里重复展示；用户文本干净呈现。
- [ ] AC5：每个文件可展开查看其提取文本（`sop_file.content`）；默认折叠保持界面整洁。
- [ ] AC6：无文本且无上传的步骤，输入区优雅留白或不渲染，不报错、不出现空卡片。
- [ ] AC7：回看态新增的输入展示为**只读**——无输入框、无上传按钮、无执行按钮，不影响既有"重新生成"等只读操作。
- [ ] AC8：`GET /v1/sop/runs/:id/status` 的 `completed_nodes[]` 每项新增 `files` 数组（含 `file_name`/`file_url`(已签名)/`file_type`/`file_size`/`content`/`id`），不破坏既有字段与既有调用方。
- [ ] AC9：视觉与现有 SOP 步骤卡片体系一致（design token、字体阶梯、间距、四态处理），整体美观合理。

### 边界情况
- COS 未启用（本地）或 `object_key` 空 → 文件 `file_url` 回退原值，不报错。
- 签名失败（COS 异常）→ 该文件保留原 `file_url`，其余文件正常，不整体失败。
- `input` 极长（含截断标记 `...(内容过长已截断)`）→ 文本块支持滚动/折叠，避免撑爆布局。
- 文件名含特殊字符 → 已在上传时 `sanitizeFileName`；剥离逻辑按精确文件名匹配，匹配不到则保守不剥离（宁可多展示也不误删用户文本）。
- 同一步多个文件 → 图片网格 + 文件列表，数量多时合理换行/滚动。

### 权限规则
- 与现有回看页一致：用户只能看自己的运行（`/sop/runs/:id/status` 既有 user_token 鉴权 + 归属校验，不放宽）。无管理端改动。

### UI 行为规格
- 页面位置：用户端 `SOPRunView` → `StepCanvas` → `SopStepView.vue` 的只读态（`done-history` / `done-current`），位于 `OutputCard` 之上。
- 布局要求：新建只读「输入回看卡」（暂名 `ReplayInputCard.vue`）。结构：标题「你的输入」+ 文本块；下方「上传的素材」区——图片缩略图网格 + 非图片文件卡列表；每文件可展开「查看提取文本」。
- 交互模式：只读。图片点击放大/新标签打开；文件卡点击打开；提取文本点击展开/收起。无输入、无上传、无提交。
- 状态处理：无 input 且无 files → 不渲染该卡（或极简留白）；有 input 无 files → 仅文本块；有 files → 完整呈现；图片加载失败 → 占位 + 文件名兜底。
