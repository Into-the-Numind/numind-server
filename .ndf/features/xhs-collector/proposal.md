# 小红书选题采集插件 (xhs-collector) — 提案

> S1 提案 · 2026-06-23 · Standard 轨道 · 依据 S0 需求卡 + 4 项决策锁定

## §1 方案概述 [客户可见]

做一个**浏览器插件**,给有数客户(小红书 IP 陪跑机构 / 操盘手)用。客户在自己已登录小红书的浏览器里刷笔记,看到爆款 / 竞品就点页面角上的有数小浮标「采集」,这条笔记的标题、正文、封面、视频、评论、互动数据就被抓下来存进插件。攒够一批后点「导出」,有数后台把这些笔记整理成一个 **Word 文档**(docx)给客户下载——视频笔记自动转成文字稿,需要时附一段 AI 分析。这份文档就是客户的选题素材 / 竞品拆解,可直接用或喂进有数的内容生产 SOP。

**不做单独的"选题库"页面,采集完直接出文档。** 插件第一次用时一键授权绑定有数账号,全程不手动输码。

## §2 工作量与周期 [客户可见]

- 性质:**有数自有产品功能**(非对外接单,无对客报价)。
- 预估工作量:**约 15 工作日(≈ 3 周)**,单人 + AI 辅助节奏。
  - 插件本体(浮标 + 采集 + 攒批 + 导出 + 授权):~5-7 天(大头,视频直链抓取最磨)
  - 后端 ingest + docx 组装接口:~2-3 天
  - 视频转文字稿接入 + ASR 扣费补丁:~2-3 天
  - AI 分析接入(走现有计费):~1 天
  - 一键授权(授权回调 + 颁 token):~2 天
  - 网页安装入口 + 傻瓜引导页:~1-2 天
  - 联调 + S5 验收:~2-3 天
- 分发:v1 自托管 + 傻瓜安装引导(开发者模式);商店上架作为之后并行轨道(同一份插件,代码不改)。

## §3 技术可行性 [AI 内部]

### 现有功能复用
- **登录鉴权**:`user_token` 中间件现成;一键授权走 OAuth 式授权回调(网页授权页 → 颁 token 回插件存储)。
- **视频转文字稿**:`monitor/transcriber.go` 已有 video→ffmpeg→audio→ASR 链路;会议副驾的阿里云 Paraformer ASR 走 aiservice。小红书视频直链 → 下载 → 复用此链路。
- **AI 分析**:`aiservice.Chat`(封面 / 内容 / 选题分析),走 gateway 计费。
- **生成 docx**:文档系统(create_docx 复用沙箱 + 内嵌 md_to_docx.py,后端拼 markdown → docx)。
- **存储 + 下载**:COS + `GenerateSignedDownloadURL`(生成的 docx 存 COS,返回签名下载链接)。
- **图片归一化**:`internal/pkg/imageutil`(封面,如需)。
- **积分不足拦截**:前端 `InsufficientCreditsDialog` 现成。

### 技术风险
1. **小红书改版致采集失效**(选择器 / `__INITIAL_STATE__` 结构变)→ 持续维护税。缓解:照逆向插件的多 fallback 路径写,监控采集失败率,改版时快修(因跑真实登录态、人工节奏,塌频率低)。
2. **视频直链时效**:小红书视频直链带签名、可能很快失效。缓解:采集时即抓直链,导出尽快下载转写;时序细节 S2 定(可能"采集即触发下载缓存")。
3. **ASR 扣费是新逻辑**:现系统 ASR"只记成本、不扣用户"(见 billing 心智模型)。按客户原则"调云服务就扣",需新增按 ASR 时长(0.00008 元/秒)扣积分的逻辑。小改,但**不是纯复用**,S2 定扣费点(Reserve/Reconcile 还是按用量结算)。
4. **一键授权回调**:插件 ↔ 有数 OAuth 式流程(授权页 → 回调颁 token → 插件存)。标准做法,风险低,S2 定契约。
5. **评论懒加载**:只采页面已加载的热门前 N 条,非全量(已在需求卡注明范围)。
6. **分发(开发者模式)对小白不友好**:非技术风险,已接受 → 傻瓜图文/视频引导 + 客服兜底。

### 涉及仓库

- [x] numind-web-v3 — 网页"安装插件"入口 + 傻瓜引导页 + 授权页;**浏览器插件本体**作为新工件放此仓库新目录(如 `extension/`),S2 定目录

## §4 产品需求定义 — PRD [AI 内部 — 不要为可读性简化]

### 用户故事
- 作为有数客户(IP 操盘手),我需要刷小红书时一键采集爆款 / 竞品笔记,以便快速攒选题素材而不用手动复制粘贴。
- 作为有数客户,我需要把采集的一批笔记导出成 Word 文档(含视频文字稿、可选 AI 分析),以便做选题 / 竞品拆解或喂内容生产 SOP。
- 作为有数客户,我需要第一次用插件时一键授权绑定有数账号,以便后续采集 / 导出免登录、不手动输码。

### 验收标准
- [ ] 在已登录小红书的浏览器,插件浮标可见且可拖动;点「采集」成功抓取一条笔记的**锁定字段集**(笔记ID / 类型 / 标题 / 正文 / 标签 / 封面图 / 链接 / 发布日期 / 视频链接 / 点赞 / 收藏 / 评论数 / 评论内容前N / 作者名 / 作者主页链接 / 作者粉丝数),阅读数不采。
- [ ] 采集多条后点「导出」,后端异步生成一个可下载 docx,内含每条笔记字段;视频笔记含转写文字稿;(可选开启时)含 AI 分析段。
- [ ] 视频转文字稿调用**扣积分**;AI 分析调用**扣积分**;采集与拼 docx **不扣**。
- [ ] 一键授权:首次用插件 → 弹有数授权页 → 点同意 → 插件绑定账号;后续采集 / 导出无需再登。
- [ ] 未授权 / token 失效时,插件提示重新授权,**不静默失败**。
- [ ] 积分不足时,导出阻断并提示充值(走现有积分不足弹窗逻辑)。

### 边界情况
- 小红书未登录 → 提示"请先登录小红书"。
- 采集到的视频直链已失效 → 该条转写降级跳过,docx 标注"视频转写失败",**不阻断整批**。
- 同一笔记重复采集 → 按笔记 ID 去重。
- 空批次点导出 → 提示"请先采集笔记"。
- 视频转写耗时(异步)→ 导出走异步:提交 → 生成中 → 完成可下载,UI 告知"处理中"。
- 部分笔记转写 / 分析失败 → 整批仍出 docx,失败项标注。
- 网络 / 后端错误 → 插件提示重试。

### 权限规则
- 仅登录的有数用户可用(用户端 `user_token`)。
- 采集本身不门控;**导出**因用到 ASR/LLM,需积分(沿用现有计费 + 免费模型/会员逻辑,有积分即可用)。
- 面向 B 端机构客户;走用户端鉴权,不涉及管理端。

### UI 行为规格
- **插件浮标**:小红书页面右下角悬浮按钮(可拖动),点开含「采集」;「导出」入口在插件 popup 或浮标菜单。
- **插件 popup**:授权状态 / 已采集数量 / 导出按钮 /(可选)AI 分析开关。
- **有数网页**:一个"安装采集插件"入口(带傻瓜安装引导:下载 → 解压 → 开发者模式 → 拖入,图文 + 视频)+ 授权回调页。
- **状态处理**:loading(导出生成中 spinner)/ empty(未采集时导出给提示)/ error(失败提示重试)/ success(给下载链接)。
