# 小红书选题采集插件 (xhs-collector) — 提案

> S1 工件 · Standard 轨道 · 依据 S0 需求卡 + 4 项决策(2026-06-23/24 与用户敲定)。
> 数据落地经复议从「导出 docx」改为 **B = 有数自建累积选题库表**(理由见 §1)。

## §1 方案概述 [客户可见]

做一个**浏览器插件 + 有数里的「选题库」**:

- 客户在自己已登录小红书的浏览器里刷笔记,看到爆款 / 竞品就点页面角上有数小浮标的「采集」,这条笔记的全部字段(标题 / 正文 / 封面 / 视频 / 评论 / 标签 / 作者 / 互动数等)被抓下来。
- 采集的笔记进入**有数的「选题库」**——一张持续累积的表,**每采一篇 = 一条记录**;有数自动对每条做 AI 分析,把"分析后的数据"(选题角度、爆款原因等,具体 S2 定)写进同一条记录。
- 客户在有数里有个**选题库列表页**,能看到所有累积的笔记 + 分析,可筛选 / 排序,直接用来选题或喂进内容生产 SOP。
- 视频笔记自动转成文字稿一并入库。
- 需要时可把选题库(或选中的若干条)**导出成一份 Word 报告**(可选功能,不是主存储)。
- 插件第一次用一键授权绑定有数账号,全程不手动输码。

**明确范围**:只做小红书;数据落在**有数自己的选题库(累积表)**,不连飞书;不做抖音。

**为什么是累积表而不是 docx**:选题库本质是"一行一条、持续长大、能筛能排"的结构化记录;docx 做不断累积的库会越来越笨重(每次要么重生成整篇、要么散成一堆文档)。表是天然形态,还能直接喂 SOP。docx 仅作"导出报告"。

**分发**:v1 自托管 + 傻瓜安装引导(开发者模式);同一份插件并行提交 Chrome/Edge 商店,审过再多一条一键装的路(审核不影响 v1 上线)。

## §2 工作量与周期 [内部功能,无对外报价]

预估 **~12 工作日**(采集逻辑靠复用 plugin3.2.1 源码,省下采集那块最难调的工作):

| 块 | 内容 | 量级 |
|---|---|---|
| 插件采集 + 浮标 | 搬 + 适配 plugin3.2.1 的 DOM/`__INITIAL_STATE__` 采集 + 浮标 / popup | ~2-3 天(复用) |
| 插件改造 | 拆掉原飞书 / 卖家后端调用 → 改为发有数 + 一键授权前端 | ~1-2 天 |
| 后端 ingest + 选题库表 | 接收笔记 → 去重入库(源字段 + 分析字段)+ 列表 / 查询端点 | ~2-3 天 |
| AI 分析接入 | 每条走 aiservice 出分析字段(扣分) | ~1 天 |
| 视频转文字稿 + ASR 扣费补丁 | 复用 transcriber + 补 ASR 扣费(现状只记成本不扣) | ~2 天 |
| 选题库列表页 (web-v3) | DataTable 看 / 筛 / 排 + 导出报告按钮 + 安装入口 / 授权页 | ~2-3 天 |
| docx 导出报告(可选) | 从选中记录拼 Word | ~1 天 |
| 一键授权(后端回调) | 授权页 + 回调颁 token | ~2 天 |
| 联调 + S5 验收 | | ~2-3 天 |

> 比 docx 版多了"选题库列表页",但 docx 从主存储降为可选导出、变简单;净额仍 ~12 天。S2/S3 钉死后精确。
> 维护税(长期):小红书改版致采集失效,需持续小修。

## §3 技术可行性 [AI 内部]

### 现有功能复用
- **采集逻辑**:直接搬 plugin3.2.1 的 `content.js` 采集(DOM 选择器 + `__INITIAL_STATE__` 视频直链),最难调的部分白捡(不照搬业务代码,只取采集手法)。
- **登录鉴权**:`user_token` 中间件;一键授权走 OAuth 式回调颁 token。
- **累积表 / 列表页**:GORM model + store(标准三层);前端 DataTable 组件现成(管理端表格风格)。
- **AI 分析**:`aiservice.Chat`,走 gateway 计费 + Langfuse。
- **视频转文字稿**:`monitor/transcriber.go`(video→ffmpeg→audio→ASR)+ 会议副驾 Paraformer。
- **导出 Word(可选)**:`create_docx` 沙箱 + COS + `GenerateSignedDownloadURL` 签名下载。
- **图片归一化**:`internal/pkg/imageutil`(封面)。
- **积分不足拦截**:前端 `InsufficientCreditsDialog`。

### 技术风险
1. **小红书改版致采集失效**(选择器 / `__INITIAL_STATE__` 结构变)→ 维护税。缓解:照逆向的多 fallback 写 + 监控失败率 + 快修(跑真实登录态、人工节奏,塌频率低)。
2. **ASR 扣费是新逻辑**:现系统 ASR"只记成本、不扣用户"。按原则需新增按时长(0.00008 元/秒)扣分,S2 定扣费点(Reserve/Reconcile 还是按用量结算)。触计费,repro-first + 双审。
3. **视频直链时效**:带签名、可能很快失效。缓解:采集即抓直链,尽快下载转写;时序 S2 定。
4. **选题库表 schema**:源字段(已锁)+ 分析字段(LLM 产出,具体字段 S2 定)。
5. **一键授权回调**:插件 ↔ 有数 OAuth 式流程,标准做法,S2 定契约。
6. **评论懒加载**:只采已加载热门前 N 条(需求卡已注明范围)。
7. **分发(开发者模式)对小白不友好**:非技术风险,傻瓜图文 / 视频引导 + 客服兜底。

### 涉及仓库
- [x] numind-server — ingest 端点 + 选题库表 / store + AI 分析 + ASR 扣费补丁 + 授权回调 + (可选)docx 导出
- [x] numind-web-v3 — 选题库列表页 + 安装入口 + 傻瓜引导页 + 授权页;**浏览器插件本体**作为新工件放此仓库新目录(如 `extension/`),S2 定目录
- [ ] numind-admin-web — 不涉及

### AI 可观测性
- [x] 涉及 LLM 调用:**是**(AI 分析)+ ASR(云服务)
- Trace 起点:笔记入库后触发分析的 biz 函数(每条 / 每批建 trace)
- Generation 点:① `xhs-note-analysis`(LLM 分析,记 model/input/output/token)② `xhs-video-asr`(转写,记时长 / 成本)
- 关键元数据:`user_id`、`note_id`、`batch_id`
- 优雅降级:`if tc != nil` 守卫

## §4 产品需求定义 — PRD [AI 内部 — 不要为可读性简化]

### 用户故事
- 作为有数客户(IP 操盘手),我需要刷小红书时一键采集爆款 / 竞品笔记,以便快速攒选题素材而不用手动复制粘贴。
- 作为有数客户,我需要采集的笔记**自动累积进有数选题库、自动出 AI 分析**,以便在一个地方看 / 筛 / 选题,并喂进内容生产 SOP。
- 作为有数客户,我需要(可选)把选题库或选中的几条**导出成 Word 报告**,以便对外分享或存档。
- 作为有数客户,我需要第一次用插件时一键授权绑定有数账号,以便后续采集免登录、不手动输码。

### 选题库表字段(S2 锁定具体 schema)
- **源字段**(已锁,见 requirement.md):笔记ID / 类型 / 标题 / 正文 / 标签 / 封面 / 链接 / 发布日期 / 视频链接 / 视频文字稿 / 点赞 / 收藏 / 评论数 / 分享数 / 评论内容(前N)/ 作者名 / 主页链接 / 粉丝数 / 采集时间。
- **分析字段**(LLM 产出,具体 S2 定):如 选题角度、爆款原因、可借鉴点、目标人群、情绪钩子等。

### 验收标准
- [ ] 点「采集」成功抓取锁定字段集(逐字段核对);按笔记ID去重。
- [ ] 采集的笔记入**选题库表**;每条自动出 AI 分析字段;视频笔记含转写文字稿。
- [ ] **选题库列表页**能看到累积记录、可筛选 / 排序;loading / empty(含采集引导)/ error / success 四状态齐全。
- [ ] (可选)导出选中记录为 Word 报告,可下载打开。
- [ ] 扣费:**AI 分析扣分、视频转文字稿扣分;采集 / 入库 / 看列表不扣**。积分不足拦截提示。
- [ ] 一键授权:点同意 → 绑定 → 后续免登;授权失效提示重新授权,**不静默失败**。
- [ ] 非技术用户能照安装引导独立把插件装好。

### 边界情况
- 小红书未登录 → 提示"请先登录小红书"。
- 视频直链失效 → 该条无转写,标注,不阻断入库。
- 重复采集同一笔记 → 按笔记ID去重(更新还是跳过,S2 定)。
- AI 分析 / 转写失败 → 记录仍入库,分析字段留空 + 标注,不阻断。
- 积分不足 → 采集 / 入库可继续(不扣),但分析 / 转写在扣费动作前阻断并提示充值。
- 评论懒加载 → 只取热门前 N 条。

### 权限规则
- 仅登录的有数用户可用(用户端 `user_token`)。
- 采集 / 看选题库不门控;分析 / 转写因用到 ASR/LLM 需积分(沿用现有计费 + 免费模型 / 会员逻辑)。
- 面向 B 端机构客户;走用户端鉴权,不涉及管理端。

### UI 行为规格
- **插件浮标**:小红书页面角落悬浮按钮(可拖动),点「采集」;popup 显示授权状态 / 已采集数。
- **选题库列表页**(web-v3):DataTable,列 = 源字段 + 分析字段;支持筛选 / 排序;每行可看详情;顶部「导出报告」按钮;状态:loading / empty(含引导)/ error / success。
- **有数网页**:"安装采集插件"入口(带傻瓜安装引导:下载 → 解压 → 开发者模式 → 拖入,图文 + 视频)+ 一键授权回调页。
