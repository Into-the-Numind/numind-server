# ADR 0021: 真实飞书验收在 dev 运行时进行

- 日期：2026-07-15
- 状态：已采纳
- 决策者：用户（明确授权）

## 背景

原计划把 Task 24 定义为本机 S5 真实租户验收。本机已具备 `lark-cli` 1.0.68，但受控执行器要求的固定路径和持久 Keyring 均应由实际服务运行时提供；当前开发机没有这两个系统级条件。产品本身运行在云端容器，而 dev 部署链路会安装固定绝对路径的 CLI、挂载持久运行目录并加载受限 secrets 文件。

## 决策

保留所有已通过的本地自动化验证。按用户授权，先使用 `ndf-done` 将后端和前端原子合并到 `develop`，只部署云端 dev，再执行真实账号验收。dev 服务器的 `NUMIND_FEISHU_KEYRING` 使用独立、持久、权限 0600 的 secrets 文件注入，密钥绝不写入 Git、镜像、YAML、日志或本 ADR。

不部署生产。验收范围保持不变：Docs/Base/Wiki 创建、读取、更新，分阶段授权，重启恢复，撤销后重新授权，unknown 写结果，解绑，双用户隔离和幂等副作用。飞书应用创建、权限审批和写入真实资源是用户控制的外部副作用，仍在执行该步骤前由用户于飞书官方页面确认。

## 后果

本次 NDF 的 S5 与 S6 顺序是一次经用户授权、已记录的例外：真实运行时覆盖本机受控路径问题，但并不让未验证项降级。若 dev 健康、固定 CLI、Keyring composition 或真实验收任一失败，停止在 dev，回到 S4 修复；生产发布仍需要独立的 S7 授权。
