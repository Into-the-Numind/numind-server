# RAG 检索基线报告（baseline）

> 这是「把 RAG 打造成业界一流」科学闭环的**第 0 步基准**。后续每项改进（混合检索 → 查询处理 → rerank 阈值调优 → 上下文组装）都对照本表「改前改后跑分」，涨了留、降了回退。

## 跑分环境

- 日期：2026-06-17
- 端点：`POST /v1/admin/rag-eval/retrieve`（用户服务 dev，端口 9091，admin-gated）—— 复用**生产 chatbot 同一个 `retrieve.Service`**，即评估测的就是真实链路
- 语料（黄金集 `golden.yaml`）：`user_id=25` 的莫小派销售 KB 4 篇 `[127 案例库, 128 产品手册, 129 百问百答, 146 陪跑优势]`，22 题覆盖 5 题型
- 指标：recall@k / MRR@k / nDCG@k，均在 top-k=5 截断处计算（口径一致）
- 两种模式：
  - **prod**：对齐 chatbot 产线（rerank 阈值 0.6 + no_floor + 原话检索）—— 这是用户实际体验到的检索
  - **raw**：不设阈值（检索+rerank 原始排序）—— 衡量**检索能力上限**

## 基线数字（k=5）

### prod 模式（= 真实 chatbot 检索）

| 题型 | recall@5 | MRR@5 | nDCG@5 | n |
|------|---------|-------|--------|---|
| in_kb_single | 1.000 | 0.938 | 0.954 | 8 |
| exact_term | 1.000 | 1.000 | 1.000 | 5 |
| paraphrase | **0.333** | 0.333 | 0.333 | 3 |
| in_kb_multi | 0.667 | 0.500 | 0.333 | 3 |
| out_of_kb（拒答准确率） | **1.000** | — | — | 3 |
| **总体** | **0.864** | **0.789** | **0.770** | 22（库内 19） |

### raw 模式（检索能力上限，不设阈值）

| 题型 | recall@5 | MRR@5 | nDCG@5 | n |
|------|---------|-------|--------|---|
| in_kb_single | 1.000 | 0.938 | 0.954 | 8 |
| exact_term | 1.000 | 1.000 | 1.000 | 5 |
| paraphrase | **1.000** | 1.000 | 1.000 | 3 |
| in_kb_multi | **1.000** | 0.833 | 0.538 | 3 |
| out_of_kb（拒答准确率） | 0.000 | — | — | 3 |
| **总体（库内）** | 库内 recall **1.000** | 0.947 | 0.908 | 22（库内 19） |

> raw 模式 out_of_kb 拒答=0 是预期的：没有阈值，任何 query 都会返回 top 结果，所以库外题必然「召回到东西」。out_of_kb 的防编造能力只在 prod 模式（带阈值）有意义。

## 关键结论（基线告诉我们什么）

1. **向量检索本身已经很强**：raw 模式下，全部 19 道库内题 recall@5 = 1.000、MRR@5 = 0.95 —— 正确文档几乎总在第 1 位。说明 embedding + 向量召回 + rerank 排序在这个语料上没有明显短板。
2. **prod 的全部召回损失来自 0.6 rerank 阈值**：prod 比 raw 掉的 3 题（q10「收费偏高」改写、q16「培训机构」改写、q18 多文档问法）在 raw 里都是 rank-1，只是 rerank 分 < 0.6 被阈值丢弃。改写/口语化 query 的 rerank 分系统性偏低。
3. **0.6 阈值同时换来完美的库外拒答**（out_of_kb 拒答 1.000）。所以这是一个**召回 vs 拒答精度的权衡点**，不是单纯的 bug。
4. **指向下一步**：
   - **rerank 阈值调优**（计划第 ④ 步）：直接针对结论 2/3——找一个在「不漏改写题」与「不放库外题」之间更优的阈值/策略（如按 query 类型动态阈值、或 top-1 保底 + 阈值并用）。
   - **查询处理**（计划第 ③ 步，改写/HyDE）：把口语化 query 规整后再检索，提升 paraphrase 类的 rerank 分。
   - **混合检索**（计划第 ② 步）：本语料纯向量已达上限，混合检索的增益预计主要体现在**专有名词/长尾**（exact_term 现已 1.000，但更大更杂语料里关键词召回的价值会显现）。

## 如何复现

```bash
# 端点在用户服务(9091),admin 登录在 admin 服务(9099) —— 分别指定
export NUMIND_ADMIN_PASSWORD=<admin_pw>
python3 scripts/rag_eval/run_eval.py --golden scripts/rag_eval/golden.yaml \
    --login-url http://<dev>:9099 --base-url http://<dev>:9091 --user admin --k 5
# 加 --raw 看检索上限(无阈值)。dev 9091/9099 不对公网开放时,先开 SSH 隧道再用 localhost。
```

## 局限（诚实声明）

- 样本量小（22 题、4 篇文档、单一用户语料），数字波动敏感；趋势可信，绝对值仅供同语料对比，不要跨语料横向比。
- 黄金集标注由 AI 基于真实 chunk 内容起草，**建议业务方抽查**（标注准 = 尺子准）。
- 只测**检索**（doc 命中/排序），未测端到端**答案忠实度**（LLM-as-judge 是后续增量）。
