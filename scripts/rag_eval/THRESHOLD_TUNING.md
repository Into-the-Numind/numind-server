# rerank 阈值调优分析（计划第④步）— 结论：保持 0.6，不改

> 2026-06-17。方法：先用确定性扫描（offline 跑遍阈值族，对每条 golden query 捕获的 rerank 分做过滤模拟，self-validate 过——global T=0.6 精确复现线上基线 MRR=0.789），再用多 agent workflow（4 分析视角 + 3 对抗证伪 + 1 综合）在真实数据上做「改前的稳健性/过拟合/幻觉风险」审查。**3/3 对抗 agent 否决了「降到 0.3」**，综合结论 `commit_now=False`。

## 当前线上配置
`internal/numind/biz/chatbot/stream.go:315-316`：`RerankMinScore: 0.6` + `RerankNoFloor: true`（F2 设定，刻意丢弃 40-50% 低相关度内容；no_floor=true → 无好匹配时返回空，让 bot 用 system prompt 回答而非拿弱 chunk 硬凑——这是 chatbot 的**首要防幻觉机制**）。

## 扫描结果（k=5，in-KB recall / MRR / out_of_kb 拒答；19 库内 + 3 库外题）
| 策略 | recall | mrr | oob 拒答 | 评 |
|---|---|---|---|---|
| global T=0.0 | 1.000 | 0.947 | 0.000 | 全返回，从不拒答 |
| **global T=0.30** | 0.895 | 0.842 | 1.000 | 表面「白嫖」：比 0.6 多召回 1 题且拒答仍满 |
| global T=0.40–0.70（含线上 0.6） | 0.842 | 0.789 | 1.000 | 当前所在的安全平台 |
| top1_floor（任意 T≤0.7） | 1.000 | 0.947 | **0.000** | 永远保 rank-1 → 从不拒库外，**淘汰** |
| score_gap（任意 delta） | 1.000 | 0.947 | **0.000** | 同上，**淘汰** |

## 为什么不降到 0.3（核心论证）
1. **0.6→0.3 的全部收益 = 1 道题**（q16，paraphrase，正确 chunk 重排分 0.3358）。窗口仅 (0.30, 0.3358] 宽 0.036，T=0.35 就丢掉——在 rerank 分 run-to-run 漂移范围内，是对 19 题/1 用户/4 文档小样本的过拟合。
2. **「T=0.3 拒答仍 1.0」证据薄弱**：3 道库外题是 weather/python/科幻片等极易判的 off-domain（最高分 0.035）。真正危险的 **hard negative**（**在域但答案不在这 4 篇里**的销售问题，如退款政策/竞品对比/平台细则）golden 集**完全没采样**——而这恰是会重排到 0.3-0.55、在 T=0.3 下漏进来变成「有据幻觉」的类别。
3. 把全局阈值降到 0.3 等于**重新放进 F2 当初刻意丢弃的 40-50% 噪声**；golden 只量**文档级召回**，量不到答案质量回归这一面的代价。
4. q16/q10/q18 都是改写/多文档 miss（正确 chunk 分 0.3358/0.1721/0.066），其中 2 道任何阈值都救不回——**正确的杠杆是 query 侧处理（③ 改写/HyDE）**，它抬高「正确 chunk」的分，而非降低对所有 chunk 的门槛，保住拒答地板。

## 决策
- **保持 `RerankMinScore: 0.6` + `RerankNoFloor: true` 不动**（本步零代码改动）。
- 若将来确有需求下调：**0.40 是唯一可接受下限**（本集 metric-neutral，仍在安全平台之上），**禁止 0.30**（除非另加 grounding/answerability gate 且 hard-negative 拒答已实测达标）。
- 真正的召回杠杆 = **③ 查询处理**（chatbot 专用**中性**改写/HyDE——**不能**直接复用 salesrag 的销售意图改写，会污染知识问答，见 stream.go F1 注释；当前 `RewriteQuery:false` 就是这个原因）。

## 后续（按序）
1. **【阻塞前提】golden 集补 hard negative**：加若干「在域但答案不在 KB」的销售问题（expected 空），在 0.6/0.4/0.3 上实测拒答率——这是任何阈值下调的前置门槛，也直接补上本分析最大的盲点。
2. **③ 查询处理**（下一个真正的 feature）：chatbot 中性改写/HyDE，预期把 q16（及可能 q10/q18）抬到 0.6 以上，**不动拒答地板地**恢复召回；做完用 harness 复跑对比。
3. prod 近阈值日志（top 重排分落在 [0.30,0.50] 的检索打点 + query 文本），积累真实泄漏数据再谈调阈值。
4. 改全局阈值前需在 ≥2 个其它租户/KB 上复验（本分析仅单用户单语料）。

> 这是一次「测两次、切一次」：朴素扫描看着像免费午餐（+1 题、拒答不掉），对抗审查揭穿了它是噪声级收益 + 削弱未被采样类别上的防幻觉保证。④ 的科学结论就是**不改**，把力气放到 ③ 和 hard-negative 扩集。
